# modbus-sim — Modbus TCP сервер для стенда WinCC OA

Свой сервер вместо `mtcpServerEmulator`. Причина: GUI-эмулятор не умеет
перечитывать конфигурацию без перезапуска — приходится вручную останавливать
приложение и заново выбирать файл.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `modbus-sim.ps1` | управление: `start` / `stop` / `restart` / `status` |
| `server.js` | сам сервер, без зависимостей |
| `map.json` | карта адресов, перечитывается на лету |
| `package.json` | только метаданные и скрипты, зависимостей нет |
| `.gitignore` | журналы работы и `node_modules` |

## Почему не библиотека

Обе предложенные как замена — только клиенты, серверной части в них нет:

| Пакет | Что внутри |
| --- | --- |
| `node-modbus` | зависимость `serialport` ради RTU-клиента, нативная сборка падает на Windows. Установлен с `--ignore-scripts`, серверных файлов нет |
| `jsmodbus` 5.0.0 | 27 файлов `.js`, ни одного `createServer` |

Поэтому сервер написан здесь, без зависимостей.

## Запуск

Пользуйся скриптом — он умеет отсоединять процесс от консоли, дожидаться
порта и переиспользовать уже работающий экземпляр:

```
tools\modbus-sim\modbus-sim.ps1              запустить, если не запущен
tools\modbus-sim\modbus-sim.ps1 restart      перезапустить
tools\modbus-sim\modbus-sim.ps1 stop         остановить
tools\modbus-sim\modbus-sim.ps1 status       состояние
```

Параметры: `-Port` перекрывает порт из `map.json`, `-Map` задаёт свой файл
карты, `-VerboseLog` включает запись запросов чтения в журнал.

Прямой запуск тоже работает, но консоль на нём зависнет:

```
node server.js
```

Поднимает порт из `map.json`. Если порт занят — остановите
`mtcpServerEmulator`, он конкурирует за 504.

## Карта

Правьте `map.json` — сервер следит за файлом и подхватывает изменения
**сам, без перезапуска**. Проверено: диапазон температуры изменён с
15…35 на 100…200, через три секунды WinCC OA уже читала 163.79 вместо 34.28.

Изменения адресов и диапазонов применяются за секунды, перезапуск WinCC OA
или драйвера не нужен.

### Структура

```json
{
  "port": 504,
  "wordOrder": "CDAB",
  "devices": [
    { "id": 1, "name": "Насос",
      "coils":   [ { "addr": 0, "name": "Pump_Start", "gen": { "type": "toggle", "periodMs": 5000 } } ],
      "holding": [ { "addr": 0, "count": 1, "name": "Pump_Speed_Set", "gen": { "type": "ramp", "min": 40, "max": 90, "periodMs": 8000 } } ] }
  ]
}
```

### Генераторы значений

| `type` | Параметры | Поведение |
| --- | --- | --- |
| `const` | `value` | постоянное значение |
| `toggle` | `periodMs` | переключается true/false через `periodMs` |
| `sine` | `min`, `max`, `periodMs` | синусоида в диапазоне |
| `sineInt` | `min`, `max`, `periodMs` | синусоида с округлением до целого |
| `ramp` | `min`, `max`, `periodMs` | пилообразное значение |
| `rand` | `min`, `max` | случайное целое |

`count` — число 16-битных регистров: `1` — int16, `2` — float, `4` — double.

### Порядок слов

`wordOrder` — `"CDAB"` (низшее слово первым, значение по умолчанию) или
`"ABCD"` (старшее первым). Проверено, что драйвер WinCC OA читает `CDAB`
корректно: пары «вещественное + целое» сходятся, например `Temperature`
163.79 и `Temperature_Int` 1638.

## Непрерывность адресного пространства

Адреса **должны идти подряд**. Драйвер группирует запросы, и разрыв внутри
группы останавливает чтение блока — на этом уже наступали грабли. Сервер
проверяет карту при загрузке и предупреждает:

```
[карта] ВНИМАНИЕ slave 1 holding: разрыв перед адресом 20, ожидался 4.
```

## Поддерживаемые коды функций

| FC | Операция | Состояние |
| --- | --- | --- |
| 1 | Read Coils | проверен |
| 2 | Read Discrete Inputs | реализован |
| 3 | Read Holding Registers | проверен |
| 4 | Read Input Registers | реализован |
| 5 | Write Single Coil | реализован, но драйвер шлёт FC15 — см. ниже |
| 6 | Write Single Register | реализован, но драйвер шлёт FC16 — см. ниже |
| 15 | Write Multiple Coils | **проверен фактически драйвером** |
| 16 | Write Multiple Registers | **проверен фактически драйвером** |

Неизвестный код возвращает исключение `0x01`, неверный адрес — `0x02`,
неверное значение — `0x03`.

## Драйвер группирует записи

Направление `DPATTR_ADDR_MODE_IO_POLL` (7) позволяет и читать, и писать, но
драйвер **не шлёт одиночные коды**. Для одного coil пришёл FC15, для одного
регистра — FC16:

```
[write] slave 6: FC15 coils 5..5 (1 байт)
[write] slave 6: FC16 holding 3..3 (Valve_Reg_Test)
```

## Направление 5 не доходит до устройства

`DPATTR_ADDR_MODE_OUTPUT_SINGLE` (5) — «выход, одиночное соединение по
subindex». При нём драйвер держит значение локально и запрос на устройство не
отправляет вовсе: в журнале сервера записи не появлялись, хотя `dpSetTimedWait`
возвращал `0` и значение читалось обратно.

## Журнал

`server.log` рядом с сервером. Запросы чтения не пишутся — их поток
постоянный. Записи пишутся всегда: код функции, slave, адрес и имя регистра.

Включить и чтение — переменная окружения `VERBOSE=1`.

## Проверка изменений

`examples/11-address/14_read_temp.ctl` — читает температуру и её десятичное значение. Запустите,
измените диапазон в `map.json`, запустите снова: значение должно измениться
без перезапуска сервера.

Примеры WinCC OA: `examples/11-address/07_address_map.ctl` — чтение всей
карты, 41 элемент; `10_address_modbus_write.ctl` — запись, 5 проверок.

## Состояние окружения

Эмулятор `mtcpServerEmulator` остановлен, порт 504 держит этот сервер.
В реестре `HKCU\Software\ModbusEmul` выставлено `AutoLoadConfig = 1` и
`ConfigPath` — на случай возврата к GUI-эмулятору. Копия конфигурации
лежит в `C:\modbus_emul\more_tag.xml`.
