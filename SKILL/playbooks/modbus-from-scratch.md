# Modbus: от референса пользователя до работающих точек

Проверено дважды на двух разных картах: одна с одним устройством на 40
элементов, другая на шесть устройств и 43 элемента. Обе прошли с первого
раза, потому что скрипт точки генерируется, а не пишется руками.

## Порядок

1. Спросить у пользователя, чего не хватает в референсе: порядок слов и
   разрядность 32-битных записей. Это единственное, что нельзя вывести из
   данных пользователя.
2. Собрать карту в схему `map.json`.
3. Проверить карту валидатором.
4. Настроить узлы подключения, если они ещё не настроены.
5. Запустить эмулятор, если реального устройства нет.
6. Сгенерировать CTL и запустить.
7. Показать пользователю таблицу соответствия и спросить, оставлять ли точки.

## Схема карты

```json
{
  "//wordOrder": "CDAB - драйвер WinCC OA 3.18 ждёт младшее слово первым",
  "//writable": "записываемый параметр помечается writable: true, иначе он будет только для чтения",
  "port": 504,
  "wordOrder": "CDAB",
  "devices": [
    {
      "id": 1,
      "name": "SmartTempPress",

      "input":   [ { "addr": 0, "name": "Device_Ready", "gen": { "type": "const", "value": 1 } } ],

      "coils":   [ { "addr": 0, "name": "Enable_Heating", "gen": { "type": "toggle", "periodMs": 8000 } } ],

      "ireg":    [ { "addr": 0, "count": 1, "signed": true,  "name": "Current_Temperature",
                     "gen": { "type": "sineInt", "min": 180, "max": 320, "periodMs": 15000 } },
                   { "addr": 1, "count": 2, "signed": false, "name": "Energy_Consumption",
                     "gen": { "type": "sine", "min": 120, "max": 480, "periodMs": 21000 } } ],

      "holding": [ { "addr": 0, "count": 1, "signed": true, "writable": true, "name": "Temperature_Setpoint",
                     "gen": { "type": "ramp", "min": 200, "max": 280, "periodMs": 25000 } } ]
    }
  ]
}
```

**`writable` — не украшение, а необходимое поле.** Без него любой регистр
хранения генерируется с `_direction` = 4, то есть **только чтение**. Запись
в уставку при этом не выдаёт ошибки: `dpSetTimedWait` возвращает `rc = 0`,
`_reference` заполнен, данные идут, а значение не меняется. Развилка такая:

| `writable` | `_direction` | Что получится |
| --- | --- | --- |
| не указан | 4 | запись молча не доходит до устройства |
| `true` | 7 | запись уходит (FC6/16) |
| `false` | 4 | то же, что без флага |

У катушек (`coils`) направление 7 ставится всегда, флаг не нужен. На `input`
и `ireg` флаг отвергается валидатором: записи там нет вовсе.

| Пространство | Код FC | Назначение |
| --- | --- | --- |
| `coils` | 1 | дискретные выходы, запись и чтение |
| `input` | 2 | дискретные входы, только чтение |
| `ireg` | 4 | регистры ввода, только чтение |
| `holding` | 3 | регистры хранения, чтение и запись |

`count` — сколько регистров занимает запись: 1, 2 или 4. `signed` — знаковость.

### Генераторы

Генератор описывает, как значение ведёт себя во времени, и попутно решает,
float это или целое.

| Тип | Параметры | Поведение |
| --- | --- | --- |
| `const` | `value` | постоянное значение |
| `toggle` | `periodMs` | переключение с периодом |
| `sineInt` | `min`, `max`, `periodMs` | целая синусоида |
| `sine` | `min`, `max`, `periodMs` | дробная синусоида |
| `ramp` | `min`, `max`, `periodMs` | линейное движение |
| `rand` | `min`, `max` | случайное |

**Как минимум часть сигналов должна быть динамической.** Если все значения
константы, то по карте невозможно отличить исправную работу от неверного
адреса: и то и другое даёт молчание. Валидатор предупредит об этом.

## Проверка карты

```powershell
node .\tools\modbus-sim\validate-map.js .\tools\modbus-sim\devices\smart-temp-press.json
```

Код возврата: `0` можно запускать, `1` ошибки, `2` файл не прочитан.

Проверяются: непрерывность адресов внутри блока, дубли, допустимость `count`,
тип `signed`, обязательные параметры генератора, занятость порта.

Предупреждения не блокируют запуск, но их надо прочитать. Самое полезное из
них — «все значения константы».

## Узлы подключения

Драйвер опрашивает только узлы с заполненным `DrvNumber`. Узлы без него
молчат без ошибок.

```ctl
dpSetTimedWait(0, "_Mod_Plc_2.DrvNumber",     2);
dpSetTimedWait(0, "_Mod_Plc_2.UnitAddress",   2);
dpSetTimedWait(0, "_Mod_Plc_2.HostsAndPorts", "<IP-сервера>:504");
dpSetTimedWait(0, "_Mod_Plc_2.Active",        TRUE);
```

В `HostsAndPorts` подставь адрес своего сервера — в примере он
стоит плейсхолдером. Порт `504` выбран для стенда намеренно:
стандартный Modbus TCP — это `502`, но он привилегированный и на
машине часто занят настоящим шлюзом. На боевом объекте ставь порт
своего шлюза; эмулятор умеет работать на любом, задаётся полем `port`
в `map.json` или ключом `-Port`.

Подробности и диагностика — в
[diagnosing-silent-address.md](diagnosing-silent-address.md).

## Эмулятор

Нужен, если реального устройства нет.

```powershell
$env:MODBUS_MAP = '.\tools\modbus-sim\devices\smart-temp-press.json'
$env:VERBOSE   = '1'
node .\tools\modbus-sim\server.js
```

Карта перечитывается на лету, перезапуск не нужен. Порт занят — сначала
проверь, не запущен ли прежний сервер, валидатор на это ругается кодом `1`.

Двоичные адреса: `0x00`, `0xFF`. Слово `0xFFFF` — признак того, что адрес
за пределами карты.

## Генерация точки

```powershell
node .\tools\gen-modbus-dp.js .\tools\modbus-sim\devices\smart-temp-press.json `
     --out .\examples\11-address\20_address_modbus_from_map.ctl `
     --dp STP --dpt stpt_ --drv 2
```

| Ключ | Смысл |
| --- | --- |
| `--out <file>` | куда писать CTL, обязателен |
| `--dp <префикс>` | имя точки; иначе из имени устройства |
| `--dpt <префикс>` | имя типа; иначе `<dp>_t` |
| `--drv <N>` | номер драйвера, по умолчанию 2 |
| `--keep` | не удалять существующую точку перед созданием |
| `--no-verify` | не добавлять блок проверки данных |

Скрипт сам находит группу опроса, сам создаёт тип, точку и адреса, сам ждёт
данные и проверяет: у всех элементов `quality_code = 128`, данные пришли,
часть значений меняется.

Типы проставляются по правилу из `tools/modbus-sim/regtype.js`, тем же самым,
которым эмулятор кодирует значения. Расхождение этих двух мест означало бы,
что устройство отдаёт одно, а точка читает другое.

Коллизии имён разрешаются суффиксом: одинаковое имя в `ireg` и `holding`
нельзя положить в одну точку дважды.

## Запуск

```powershell
.\examples\run-ctl.ps1 -Script .\examples\11-address\20_address_modbus_from_map.ctl
```

## Что должно получиться

```
элементов всего  : 40
quality = 128    : 40
данные пришли    : 40
значения меняется: 23
PASS=45  FAIL=0
```

И в журнале эмулятора — запросы по всем используемым пространствам:

```
[14:32:43] read   slave 1: FC1 coils 0..5
[14:32:43] read   slave 1: FC2 input 0..15
[14:32:43] read   slave 1: FC3 holding 0..19
[14:32:43] read   slave 1: FC4 ireg 0..11
```

## Независимая сверка

Если в карте есть пары «величина и та же величина в десятых долях», это
бесплатная проверка адресации и типов одновременно. На шестиустройственной
карте сошлись все четыре:

```
Temperature     25.39   Temperature_Int 254   (×10)
Pressure         3.97   Pressure_Int    397   (×100)
Level           63.12   Level_Int       631   (×10)
Flow_Instant    10.88   Flow_Int        109   (×10)
```

Совпадение возможно только при верной адресации и верном `_datatype` всех
элементов сразу.

## Проверка записи

Запись проверяется отдельно, потому что её подтверждает не значение в точке,
а запрос на устройстве.

Направление 7, а не 5: при 5 драйвер держит значение локально и на устройство
ничего не отправляет. Драйвер при этом группирует записи и шлёт `FC15` и
`FC16` вместо `FC5` и `FC6`.

Пример: `examples/11-address/10_address_modbus_write.ctl`.

## Запись в карту нового устройства

1. Добавить устройство в `map.json`, эмулятор подхватит сам.
2. Прогнать валидатор.
3. Перегенерировать CTL, не забыв `--dp` с новым префиксом.
4. Убедиться, что `UnitAddress` узла совпадает с `id` устройства в карте.
