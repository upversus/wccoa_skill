# 01. Создание: DPT, DP, проверка существования, имена

Этап «с нуля»: завести тип, создать по нему точку данных, убедиться что она есть,
проверить имя. Дальше — [02-config.md](02-config.md).

> ⛔ **Перед любым перебором:** типы и точки данных, начинающиеся с `_`, —
> **системные**. Их нельзя создавать, удалять и изменять. Любой перебор через
> `dpTypes()` / `dpNames()` обязан их отфильтровать. Подробно —
> [00-model.md, раздел 1](00-model.md#1-системные-точки-данных-правило-подчёркивание-).

## dpCreate()

**Синопсис**

```c
int dpCreate(string dpname, string dptype [, int sysnum, unsigned dpNo]);
```

**Назначение.** Создаёт точку данных `dpname` по типу `dptype`. Тип **должен
существовать до вызова**.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpname` | `string` | да | Имя создаваемой точки данных | `"TestDp1"` |
| `dptype` | `string` | да | Тип точки данных | `"ExampleDP_Int"` |
| `sysnum` | `int` | нет | Номер системы в распределённой установке | `2` |
| `dpNo` | `unsigned` | нет | Желаемый ID точки данных. **Если ID уже занят — выбирается случайный** | `4711` |

**Возврат.** `0` — успех, `-1` — ошибка.

> **Главная ловушка всей темы.** Бывает `0` (успех), но точка данных **не создана** —
> например, из-за совпадения имён. Документация прямо говорит: «in some cases the
> function returns 0 (success) but due to e.g.: name clashes the DP could not be
> created. This can be queried using getLastError()».
>
> Значит проверять только код возврата нельзя. Надёжная проверка — пара
> `dpCreate()` + `dpExists()`.

**Предусловия.** Существует `dptype` ([dpTypeCreate](01-create.md#dpTypeCreate) или
ParaMod).

**Побочные эффекты.** DP появляется в проекте и занимает номер. Если точка уже
существует — **вызов не имеет эффекта** (не ошибка, просто no-op).

**Ожидание.** **Blocking** (Waiting Control function): ждёт, пока Event Manager
создаст точку. Нет Event Manager — скрипт зависнет.

**Скрипт.** `examples/01-create/01_dpCreate.ctl`

**Типичные ошибки**

* Проверка только `rc != 0` — пропускает случай «вернул 0, но не создал». Всегда
  дублируйте `dpExists()`.
* `dpCreate` для уже существующей точки выглядит как успех. Не используйте как
  «проверку наличия».
* Имя с запрещённым символом → проверяйте `nameCheck()` до вызова.
* Дефолт `dpNo` — если не передавать, OA назначит номер сама. Для воспроизводимых
  скриптов лучше полагаться на авто-номер, а не на конкретное число.

## dpExists()

**Синопсис**

```c
bool dpExists(string dpname);
```

**Назначение.** Проверяет, разрешается ли идентификатор точки данных.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpname` | `string` | да | Идентификатор: `sys`, `DPT`, `DP`, `DPE`, config, detail или attr | `"System1:TestDp1"` |

**Возврат.** `true`, если **хотя бы одна часть** идентификатора разрешилась.

> Возвращает `true` и для пустых/неполных идентификаторов:
> `dpExists(":_original.._value")` → `true`
> `dpExists("System1:")` → `true`
> `dpExists(":")` → `true` ← **бесполезно, всегда true**

Поэтому для проверки конкретного уровня добавляют `dpSubStr()`:

```c
bool e = dpExists(dpSubStr(ident, DPSUB_DP));   // именно существование DP
```

**Предусловия.** Нет. Годится как guard перед любой операцией.

**Побочные эффекты.** Нет. Неблокирующая — можно вызывать в цикле.

**Ожидание.** Неблокирующая. Доступна UI, CTRL.

### Идентификатор точки данных как аргумент

В CTRL нет отдельного типа для DP identifier, но он приходит как `anytype` в ответе
`dpQuery*()` — и его можно передать прямо в `dpExists()`:

```c
main(mapping event)
{
  dpCreate("b1", "ExampleDP_Bit");

  dyn_dyn_anytype res;
  dpQuery("SELECT '_original.._value' FROM 'b1.'", res);
  DebugN(res);
  DebugN(dpExists(res[2][1]));      // пока жива точка — true

  dpDelete("b1");

  string name = res[2][1];
  DebugN(dpExists(name));           // после удаления — false
}
```

**Скрипт.** `examples/01-create/02_dpExists.ctl`

**Типичные ошибки**

* `dpExists(":")` в проверке «есть ли база вообще» — всегда `true`.
* Возврат `true` не означает, что существует именно то, что вы имели в виду. Для
  `DPE` используйте `dpSubStr()`.
* Ошибки — в `getLastError()`.

## dpTypeCreate()

**Синопсис**

```c
int dpTypeCreate(dyn_dyn_string elements, dyn_dyn_int types);
```

**Назначение.** Создаёт тип точки данных (DPT) с заданной структурой элементов.
Это блок, из которого потом лепятся точки данных.

> ### ⚠ ГЛАВНОЕ, ЧЕГО НЕТ В ДОКУМЕНТАЦИИ
>
> **У `dpTypeCreate()` нет параметра с именем типа. Имя типа берётся из
> `elements[1]` — из имени первого элемента. Этот же элемент становится
> корневым узлом структуры.**
>
> Проверено на CTL 3.18 (`examples/00-scenario/exp_dpt_name.ctl`, 4 из 4
> утверждений подтверждены):
>
> | Действие | Результат |
> | --- | --- |
> | `elements[1] = "dpdemo_nametest"` | создан тип `dpdemo_nametest` |
> | Корневой узел созданного типа | назван `dpdemo_nametest` |
> | Объявили тип `dpdemo_wrongname`, а в `elements[1]` положили `notdpdemo_name` | создан тип **`notdpdemo_name`**, а `dpdemo_wrongname` не существует |
> | `elements[1] = "root"`, когда тип `root` уже есть | `rc = -1`, `DM: DP already exists` |
>
> Практические следствия:
>
> * Хотите создать тип `X` — кладите `"X"` в `elements[1]`. Нет другого способа
>   задать имя.
> * Ошибка «`DM: DP already exists`» при создании типа почти всегда означает,
>   что имя уже существует — в том числе как **системный** тип или как имя
>   узла структуры.
> * Проверяйте результат через `dpTypeGet()`, а не по коду возврата.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `elements` | `dyn_dyn_string` | да | Имена элементов. **Пустая строка = спуск на уровень вниз** | `makeDynString("valve","","","")` |
| `types` | `dyn_dyn_int` | да | Типы элементов, те же индексы. `0` = уровень структуры | `makeDynInt(DPEL_STRUCT)` |

**Возврат.** `0` — ок, `-1` — ошибка (неверные типы данных или отсутствующие
аргументы).

### Как читать `dyn_dyn_string` / `dyn_dyn_int`

**Индекс массива — это НЕ уровень вложенности.** Это **порядковый номер элемента
при обходе структуры в ширину**. В ячейке лежит **путь от корня до этого элемента**:
имя элемента стоит на позиции, равной его глубине, а на позициях выше стоят пустые
строки. В `types` на этих же позициях стоят `0`.

Проверено экспериментом на CTL 3.18 (см. `examples/00-scenario/exp_dpt_shape2.ctl`):
если записать в одну ячейку несколько имён (`makeDynString("", "a", "b", "c")`),
OA создаст **один** элемент и возьмёт только позицию 2. Остальные имена будут
молча потеряны, а `dpTypeCreate()` вернёт `0`.

Правильная запись типа «корень + три дочерних элемента»:

```c
// элемент 1 — корень структуры
xxdepes[1] = makeDynString("valve");
xxdepei[1] = makeDynInt(DPEL_STRUCT);

// элемент 2 — fValue, глубина 2, путь от корня: "", "fValue"
xxdepes[2] = makeDynString("", "fValue");
xxdepei[2] = makeDynInt(0, DPEL_FLOAT);

// элемент 3 — bFlag
xxdepes[3] = makeDynString("", "bFlag");
xxdepei[3] = makeDynInt(0, DPEL_BOOL);

// элемент 4 — iCount
xxdepes[4] = makeDynString("", "iCount");
xxdepei[4] = makeDynInt(0, DPEL_INT);
```

Дополнять пустыми строками до общей ширины **можно**, но не нужно — вариант без
дополнения работает точно так же (проверено).

**Корень обязателен.** Тип без корневого `DPEL_STRUCT` не создаётся: `dpTypeCreate()`
вернёт `0`, но типа не будет. Проверять результат нужно через `dpTypeGet()`.

### Вложенная структура — как это выглядит

Тип `valve` с ветками `defaults` и `returns`:

```c
// 1: valve — корень
xxdepes[1] = makeDynString("valve");                    xxdepei[1] = makeDynInt(DPEL_STRUCT);
// 2: valve.defaults
xxdepes[2] = makeDynString("", "defaults");              xxdepei[2] = makeDynInt(0, DPEL_STRUCT);
// 3: valve.defaults.regratio — глубина 3
xxdepes[3] = makeDynString("", "", "regratio");           xxdepei[3] = makeDynInt(0, 0, DPEL_FLOAT);
// 4: valve.returns
xxdepes[4] = makeDynString("", "returns");               xxdepei[4] = makeDynInt(0, DPEL_STRUCT);
// 5: valve.returns.faults — глубина 3
xxdepes[5] = makeDynString("", "", "faults");            xxdepei[5] = makeDynInt(0, 0, DPEL_STRUCT);
// 6: valve.returns.faults.id — глубина 4
xxdepes[6] = makeDynString("", "", "", "id");             xxdepei[6] = makeDynInt(0, 0, 0, DPEL_BIT32);
```

> **Осторожно: пример в документации 3.21.6 содержит два элемента с одинаковым
> путём** — `regratio` под `defaults` (`xxdepes[3]`) и `regratio` на верхнем уровне
> (`xxdepes[12]`) записаны одинаково: `makeDynString("","","regratio","")`. Различить
> их по такому описанию невозможно. Не копируйте этот пример дословно — соберите
> структуру по правилам выше и **обязательно проверьте результат** через
> `dpTypeGet()` и `dpNames()` на созданной точке данных.

### Ссылка на тип (`DPEL_TYPEREF` = 41)

Тип-ссылка вставляется **числом 41** в `types` на позицию глубины и **именем типа**
в `names` на позицию **глубже**:

```c
// элемент: regratio со ссылкой на тип dpdemo_base_float
xxdepes[2] = makeDynString("", "regratio", "dpdemo_base_float");
xxdepei[2] = makeDynInt(0, DPEL_TYPEREF);
//                 поз.1  поз.2         поз.3
```

Имя ссылаемого типа стоит на позиции **3**, а `DPEL_TYPEREF` — на позиции **2**.

**Предусловия.** Имя DPT соответствует правилам `nameCheck()`.

**Побочные эффекты.** Появляется новый DPT, доступный `dpTypes()` и `dpCreate()`.

**Ожидание.** **Blocking** (Waiting Control function).

**Скрипт.** `examples/01-create/03_dpTypeCreate.ctl`

**Типичные ошибки**

* Забыть корневой `DPEL_STRUCT` — `dpTypeCreate()` вернёт `0`, но тип не появится.
* Передать в одной ячейке несколько имён — OA возьмёт только позицию глубины,
  остальные имена потеряются молча, без ошибки.
* `DPEL_TYPEREF` записан в `types` как текст, а не как `41`.
* Тип создан, но не проверен через `dpTypeGet()`. **Всегда** проверяйте:
  `dpTypeCreate()` может вернуть `0` при фактическом отсутствии типа.

## dpTypeGet()

**Синопсис**

```c
int dpTypeGet(string name, dyn_dyn_string &elements, dyn_dyn_int &types,
              [, bool includeSubTypes = FALSE]);
```

**Назначение.** Возвращает структуру типа точки данных в те же форматы, которые
принимает `dpTypeCreate()` — то есть **структуру DPT можно прочитать и скопировать
1:1**.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `name` | `string` | да | Имя типа | `"ExampleDP_Int"` |
| `&elements` | `dyn_dyn_string` | да (out) | Имена элементов | — |
| `&types` | `dyn_dyn_int` | да (out) | Номера типов | — |
| `includeSubTypes` | `bool` | нет | `FALSE` (по умолчанию) — подтипы не возвращаются; `TRUE` — возвращаются | `false` |

**Возврат.** `0` — ок, `-1` — ошибка (в т.ч. неопределённые переменные).

**Предусловия.** DPT существует.

**Побочные эффекты.** Нет. Неблокирующая.

```c
main()
{
  string dpt = "ExampleDP_Int";
  dyn_dyn_string names;
  dyn_dyn_int types;
  int struc = dpTypeGet(dpt, names, types);
  DebugN(dpt, struc, names, types);
}
```

**Скрипт.** `examples/01-create/04_dpTypeGet.ctl`

## dpTypes()

**Синопсис**

```c
dyn_string dpTypes(string pattern = "*", unsigned system = , bool includeEmpty = true);
```

> Синопсис в документации 3.21.6 содержит опечатку: после `unsigned system`
> пропущено значение. Смысл параметра восстанавливается из таблицы ниже.

**Назначение.** Возвращает список всех DPT проекта.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `pattern` | `string` | нет | Шаблон имени DPT | `"D*"` |
| `system` | `unsigned` | нет | Номер системы | `1` |
| `includeEmpty` | `bool` | нет | `false` — пропускать DPT, у которых нет ни одной точки данных | `true` |

> ### ⚠ Ловушка: `system = 0` возвращает пустой результат
>
> Проверено на CTL 3.18 в проекте с 262 типами:
>
> ```c
> dpTypes()                // 262 типа
> dpTypes("*", 1, true)    // 262 типа
> dpTypes("*", 0, true)    // 0 типов  ← ловушка
> ```
>
> Документация об этом молчит. Не используйте `0` как «по умолчанию» —
> либо опускайте параметр, либо подставляйте настоящий номер системы.
>
> Побочный эффект: чтобы отфильтровать пустые типы (`includeEmpty = false`),
> приходится передавать номер системы явно, потому что этот параметр третий.

**Возврат.** `dyn_string` со всеми DPT. Ошибки — в `getLastError()`.

```c
main()
{
  dyn_string ds = dpTypes("D*", 2);
  DebugN(ds);   // все DPT системы 2, начинающиеся с "D"
}
```

**Скрипт.** `examples/01-create/05_dpTypes.ctl`

**Типичные ошибки.** Список «раздувается» на DPT без данных — ставьте
`includeEmpty = false`, если он вам не нужен.

## dpNames()

**Синопсис**

```c
dyn_string dpNames(string dpPattern = "*", string dpType = "",
                   bool ignoreCase = false);
```

**Назначение.** Возвращает имена точек данных / элементов, подходящих под шаблон.
Структуры выписываются в массив в алфавитном порядке.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpPattern` | `string` | нет | Шаблон | `"TestDp*"` |
| `dpType` | `string` | нет | **Точное** имя DPT для фильтра. Подстановки не работают | `"ExampleDP_Int"` |
| `ignoreCase` | `bool` | нет | `true` — игнорировать регистр | `false` |

**Возврат.** `dyn_string` с именами. Ошибки — в `getLastError()`.

**Значения для примеров**

```c
dpNames()                          // все точки данных верхнего уровня
dpNames("*")                       // то же самое
dpNames("TestDp1.*")               // все элементы TestDp1
dpNames("Valve17.**")              // все уровни, как "*.*"
dpNames("Engine.setpoint.engineSpeed")   // точный путь
dpNames("*DP*")                    // подстрока внутри уровня
dpNames("System1:Valve17.**")      // удалённая система
dpNames(":*")                      // все конфиги
dpNames(":config.*")               // все detail-ы
dpNames(":config.detail.*")        // все атрибуты
dpNames("@somealias")              // поиск по алиасу
dpNames(dpPattern = "{*.Ala.*,*.Ala*}")  // список вариантов
```

**Предусловия.** Нет.

**Побочные эффекты.** Нет. Но это **blocking**-функция на больших базах.

**Ожидание.** **Blocking** (Waiting Control function).

**Скрипт.** `examples/01-create/10_dpNames.ctl`

**Типичные ошибки**

* Ограничение `maxDpNamesCount` в конфиге проекта. При превышении — сообщение об
  ошибке, список обрезан.
* `dpType` требует **точного** имени, `"Example*"` не сработает.
* Уровни задаются явно: `dpNames("*.*")` и `dpNames("*")` — разные результаты.

## nameCheck()

**Синопсис**

```c
int nameCheck(string &dpName [, int nameType]);
```

**Назначение.** Проверяет, что в имени только разрешённые символы, и **возвращает
исправленное имя** (поэтому параметр объявлен как `&dpName`).

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpName` | `string` | да, **ref** | Имя DP или проекта. На входе — проверяемое, на выходе — исправленное | `"/Datapoint1%"` |
| `nameType` | `int` | нет | `NAMETYPE_DP` (==1, по умолчанию) — имя DP; `NAMETYPE_PROJ` (==2) — имя проекта; `NAMETYPE_PATH` (==3) — проверки нет | `1` |

**Возврат.** `0` — только разрешённые символы, `-1` — есть недопустимые (и тогда
`dpName` содержит исправленное имя).

**Запрещённые символы в именах DP:** `. : ; * ? [ ] { } $ @`, а также
непечатаемые ASCII `\x01`…`\x20` и `\x7F`.
**Запрещённые символы в именах проекта:** `\ / " ? < > * | : ; '`

```c
main()
{
  string dpName1 = "/Datapoint1%";
  int i = nameCheck(dpName1, 1);
  if (i == 0)
    DebugN("имя корректно:", dpName1);
  else
    DebugN("имя исправлено:", dpName1);
}
```

**Скрипт.** `examples/01-create/11_nameCheck.ctl`

**Типичные ошибки**

* Забыть, что параметр — `ref`: без `&` исправленное имя не вернётся.
* `nameCheck()` проверяет и многобайтовые символы — «на глаз выглядит нормально» ≠ «валидно».

> ## Замечание об измеренном на стенде CTL 3.18
>
> * `makeUtcTime()` — **нет** в CTL 3.18, время задаётся `makeTime()`
>   (локальное).
> * `getCurrentTime()` — **есть**, отдаёт текущее **локальное** время
>   с точностью до наносекунд. Это единственный способ узнать «сейчас» из
>   CTL: `makeTime()` только конструирует время из чисел.
> * `length()`, `patMatch()`, `splitString()` — **нет** в CTL 3.18.
> * `int[]` литералы вида `{a, b, c}` — **не поддерживаются**, используйте
>   `makeDynInt(a, b, c)`.
> * **Части идентификатора точки данных разбираются функцией `dpSubStr()`**
>   с константами `DPSUB_*` (`DPSUB_SYS`, `DPSUB_DP`, `DPSUB_CONF`,
>   `DPSUB_CONF_DET`, `DPSUB_CONF_DET_ATT` и др.). Это правильный инструмент
>   для работы с путями вида `System1::_original.._value`, и он уже проверен
>   в `03-read/08_dpSubStr.ctl` — переиспользуйте его, а не строкуйте путь
>   вручную.
>
> Проверено: CTL 3.18, проект `<проект>`.
