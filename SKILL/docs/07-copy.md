# 07. Клонирование и служебные функции

`dpCopy()` создаёт точку данных **вместе с конфигурацией**. Остальные функции здесь
служебные: группы, редактирование в PARA, превью панелей.

---

## Матрица доступности в CTL 3.18

Проверено компиляцией на CTL 3.18, проект `<проект>`. Функция, которой нет в
CTL, при вызове даёт `SEVERE, 72, Function not defined` — скрипт при этом
падает целиком, а не возвращает код ошибки.

| Функция | В CTL 3.18 | Примечание |
| --- | --- | --- |
| `dpCopy()` | ✅ есть | пример `01_dpCopy.ctl`, 16/16 |
| `dpCopyBufferClear()` | ✅ есть | пример `02_dpCopyBufferClear.ctl`, 12/12 |

Все остальные функции раздела исключены из объёма: в CTL 3.18 их нет.
Общий принцип — **функция, недоступная в текущем рантайме, не реализуется**:
проверка компиляцией (`SEVERE, 72, Function not defined`) снимает вопрос, и
писать скрипты, которые гарантированно не компилируются, смысла не имеет.

Исключённые: `dpChange()` (слой PARA/UI), `getPanelPreview()` (слой UI),
`startPanelRefConstruct()` (слой GEDI — найдена в `scripts/gedi/panelDrop.ctl`,
то есть существует, но вызывается не из CTL).

Отдельно: `groupCreate()` и `groupDelete()` доступны и **реализованы**, они
живут в библиотеке `dpGroups.ctl` и требуют `#uses "dpGroups.ctl"`. Примеры —
`01-create/12_groupCreate.ctl` и `03_groupDelete.ctl` этого раздела.

## dpCopy()

**Синопсис**

```c
void dpCopy(string dpSource, string dpDestination, int &error
            [, int iDriverNumber]);
```

**Назначение.** Создаёт `dpDestination` того же типа, что и `dpSource`, **вместе с
конфигурацией**.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpSource` | `string` | да | Исходная точка данных | `"ExampleDP_Arg1"` |
| `dpDestination` | `string` | да | Создаваемая целевая точка данных | `"test3Copy"` |
| `error` | `int` | да, **ref** | Код ошибки | `0` |
| `iDriverNumber` | `int` | нет | Номер драйвера, по умолчанию **1** | `2` |

**Возврат.** `void`; ошибка — в `error`.

### Коды ошибок `dpCopy()`

| Код | Значение |
| --- | --- |
| `0` | Успех |
| `-1` | Исходная точка данных не существует |
| `-2` | Целевая точка данных пуста |
| `-3` | Квитирование невозможно |
| `-4` | Деактивация тревоги невозможна |
| `-5` | Ошибка при установке конфигов |
| `-6` | Ошибка при запросе конфигов |
| `-7` | Ошибка при запросе содержимого конфигов |
| `-8` | Не удалось создать точку данных |
| `-9` | **Целевая точка данных уже существует** |
| `-10` | Целевая точка данных не существует |
| `-11` | Неверный тип точки данных |
| `-12` | Исходная и целевая точки данных совпадают |

### Что именно копируется

* original-значения конфигурации — **только** если точка данных содержит элемент
  (node), в имени которого есть шаблон `*para*`: копируются original-значения
  элементов под этим node **и** original-значения самих элементов с `para` в имени;
* описания, единицы и форматы узлов;
* конфиги листьев (`_LEAF`);
* **неактивные** адреса шины (только неактивные выходные; активные дубликаты в WinCC OA
  невозможны).

### Чего `dpCopy()` НЕ делает

* Не копирует **классы тревог**.
* Не копирует **групповые тревоги** без подстановок.
* Не копирует **информацию блокировки**.
* **Не работает с удалёнными системами** — точка данных просто не будет скопирована.
  Для создания точки данных на удалённой системе без конфигурации используйте
  [`dpCreate()`](01-create.md#dpCreate).

### Буфер копирования

При копировании одной исходной точки данных несколько раз информация читается
**один раз**. Буфер перезагружается при копировании другой исходной точки.

**Если между копированиями изменилась исходная точка данных того же типа — буфер
надо очистить** через [`dpCopyBufferClear()`](#dpcopybufferclear), иначе скопируется
старая информация.

> Документация подчёркивает: «The user has to assure the deletion of the buffer with
> dpCopyBufferClear()!» — то есть очистка буфера **в зоне ответственности вызывающего
> кода**, автоматически её не произойдёт.

```c
main()
{
  int ierr;
  dpCopy("ExampleDP_Arg1", "test3Copy", ierr, 2);
  DebugN(ierr);
}
```

**Копирование всех original-значений, если в точке данных нет node с `para` в имени:**

```c
main()
{
  int ierr;
  dyn_string allC;
  dyn_anytype para;

  dpCopy("Test_DP_02", "Test_DP_12", ierr);
  if (ierr < 0) return;

  allC = dpNames("Test_DP_02.**:_original.._value", "TestDPT");
  dpGet(allC, para);
  for (int i = 1; i <= dynlen(allC); i++)
    strreplace(allC[i], "Test_DP_02", "Test_DP_12");
  dpSet(allC, para);
}
```

### Измерено на стенде — 16 проверок, ✅ проверено

Копирование работает: создаётся точка данных того же типа, переносятся конфиги
(проверено по `_default.._type`) и описание элемента (проверено через
`dpGetDescription`).

### Коды ошибок — измерено

| Ситуация | Документация | Измерено |
| --- | --- | --- |
| несуществующий источник | `-1` | **`-1`** ✅ |
| копирование в себя | `-12` | **`-12`** ✅ |
| цель уже существует | `-9` | **`-9`** ✅ |
| явный `iDriverNumber` | — | принимается, точка создаётся |

Проверка `-9` особенно важна: **`dpCopy()` не перезаписывает** существующую
точку. Это же означает, что повторное копирование для обновления не работает —
нужно удалять цель.

**ИМЕНА ЭЛЕМЕНТОВ — БЕЗ завершающей точки.**

**Скрипт.** `examples/07-copy/01_dpCopy.ctl` ✅ проверено, 16/16

**Типичные ошибки**

* Копирование в уже существующую точку данных → `-9`. `dpCopy()` **не** перезаписывает.
* Забытый `dpCopyBufferClear()` после правки исходной точки → копируется устаревшее.
* Ожидание, что скопируются классы тревог или блокировки — не копируются.

## dpCopyBufferClear()

**Синопсис**

```c
void dpCopyBufferClear();
```

Параметров нет, возвращает `void`.

```c
main()
{
  int x, y;
  dpCopy("System1:ExampleDP_Arg1", "test3Copy", x);
  DebugN(x);

  delay(20);              // в это время в исходную точку добавляют конфиг

  dpCopyBufferClear();    // очистить буфер
  dpCopy("System1:ExampleDP_Arg1", "test2Copy", y);
  DebugN(y);              // новый конфиг учтён
}
```

### Измерено на стенде — 12 проверок, ✅ проверено

**`dpCopyBufferClear()` работает ровно так, как описано в документации.**

| Шаг | Действие | Значение у копии |
| --- | --- | --- |
| 1 | первое копирование | `42.5` — верно |
| 2 | источник изменён на `99.75` | — |
| 3 | копирование **без** очистки | `42.5` — **старое** |
| 4 | копирование **с** очисткой | `99.75` — **свежее** |

То есть обещание документации подтверждено: без очистки приходит старое,
после очистки — актуальное. Функция `void`, ошибок не порождает.

### ⚠️ Противоположность `dpCopyConfigMergeBufferClear()`

Две функции названы почти одинаково и решают одну задачу — очистить буфер
копирования, — но ведут себя **по-разному**:

| Функция | Очистка обновляет кэш? |
| --- | --- |
| `dpCopyBufferClear()` | **да** ✅ |
| `dpCopyConfigMergeBufferClear()` | **нет** ❌ (см. `02-config.md`) |

Вывод для практики: очистку буфера нельзя считать безусловно надёжной —
после копирования результат стоит проверять чтением.

**Скрипт.** `examples/07-copy/02_dpCopyBufferClear.ctl` ✅ проверено, 12/12
