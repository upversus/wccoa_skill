# 03. Чтение: значения, типы, идентификаторы

Этап чтения. Писали конфиги в [02-config.md](02-config.md), теперь читаем.

> **Противоречие в документации 3.21.6 — разрешено измерением.** В разделе
> Assignment функция `dpGet()` помечена как *waiting Control function*, но в
> описании сказано «return value 0 only indicates that the message was correctly
> sent to Event Manager». Эти утверждения противоречат друг другу.
>
> **✓ Измерено на CTL 3.18:** `dpGet()` работает **синхронно**. В сценарии
> `full_cycle.ctl` значение, записанное через `dpSet()`, было прочитано тем же
> вызовом `dpGet()` без всякой задержки, все 27 проверок прошли. Считать
> `dpGet()` blocking-функцией не нужно; строка «waiting Control function» в
> документации ошибочна.

## dpGet()

**Синопсис**

```c
int dpGet(string dp1 | dyn_string dp1, <type1> &var1 [, string dp2, <type2> &var2, ...]);
```

**Назначение.** Читает значения атрибутов точек данных в переменные подходящего типа.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dp1`, `dp2`, … | `string` / `dyn_string` | да | Атрибуты для чтения | `"Valve17.opening:_online.._value"` |
| `var1`, `var2`, … | тип по атрибуту, **ref** | да | Куда писать. Если `dp1` — список, тип `var1` обязан быть `dyn_anytype` | `float x;` |

**Возврат.** `0` — успех, `-1` — сбой.

**Если конфиг/атрибут не указаны, подставляется:**

| Функция | Подстановка |
| --- | --- |
| `dpGet()` | `_online.._value` |

**Предусловия.** Точка данных и элемент существуют.

**Побочные эффекты.** Нет. Только чтение.

```c
float x;
dpGet("Valve17.opening:_online.._value", x);
```

### Проверка существования конфига

`dpGet()` проверяет существование **DPE**, но **не** конфиг.

Документация предлагает признак через `_type`: `0` — конфига нет, любое
другое значение — есть. На CTL 3.18 это правило **работает не всегда**,
и полагаться на него нельзя.

**Где работает.** Если тип конфига материализован, `_type` возвращает его
значение: `_address` → `DPCONFIG_PERIPH_ADDR_MAIN` (16), `_distrib` →
`DPCONFIG_DISTRIBUTION_INFO`. Это проверено на `examples/11-address/`.

**Где не работает.** У конфига `_online` значение `_type` равно `0` **даже
когда конфиг заведомо настроен** и отдаёт значения: на нативной точке,
созданной `dpCreate`, `_online.._value` читается как `42.5`, а `_online.._type`
при этом `0`.

**Что `_type` различает на самом деле** — известно ли системе *имя* конфига,
а не настроен ли он:

| Имя конфига | `dpGet` rc | Значение `_type` | Смысл |
| --- | --- | --- | --- |
| `_online` | `0` | `0` | конфиг есть, но признак не работает |
| `_alert_class` | `0` | `0` | имя системе известно, конфиг **не настроен** |
| `_nonsense_cfg` | `-1` | `0` | такого имени конфига в системе нет |

**Надёжный общий признак** — прочитать атрибут *данных* конфига и проверить
`rc`:

```c
time  t;
int rc = dpGet("rdGet.fVal:_online.._stime", t);
// rc = 0  -> конфиг настроен
// rc = -1 -> конфиг не настроен
```

Годится `_stime` или `_value`. То же верно для проверки существования
элемента: `dpGet` вернёт `rc = -1` для несуществующего DPE.

Дополнительно: путь к конфигу **корневого** элемента требует точки — `dp.:_online.._type`.
Без точки получается `dp._online.._type` и `dpGet` отвечает `DP does not exist`.
А у корневого элемента типа `struct` конфига `_online` нет вовсе: корень не
несёт значения, поэтому проверять конфиги нужно на элементе со значением.

**Скрипт.** `examples/03-read/01_dpGet.ctl`

**Типичные ошибки**

* **Один вызов — одна система.** Точки разных систем в одном `dpGet()` не работают:
  `PARAM,SEVERE, 175, this request cannot address more than one system, ...`
* Тип переменной не соответствует атрибуту.
* `dyn_anytype` обязателен, если `dp1` — массив.
* **Квадратичное падение производительности** при росте числа пар. Много значений —
  дробите на несколько вызовов.
* `dpGet("dp.")` читает `_online.._value`, а не то, что записал `dpSet("dp.")`
  (тот писал в `_original`). Всегда указывайте конфиг явно.

## dpGetAsynch()
> **⛔ Функция вне объёма работ, пример не создаётся.**
>
> Исключено по решению владельца стенда. `dpGetAsynch()` на этом стенде
> возвращает `rc = -1` даже на архивной точке `ExampleDP_Arg1`, истории у неё
> накоплено достаточно. Рабочего случая подобрать не удалось, а писать пример
> вслепую — значит выпустить код, который выглядит рабочим и не является.
> Описание ниже остаётся как справочная заметка.


**Синопсис**

```c
int dpGetAsynch(time t, string|dyn_string dp1, <type1>|<dyn_type1> &var1
                [, string|dyn_string dp2, <type2>|<dyn_type2> &var2 ...]);
```

**Назначение.** Читает значения атрибутов **на момент времени источника** `t` из базы.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `t` | `time` | да | Время источника. **Не раньше 1.1.1970 0:00 UTC** | `makeTime(1996,3,5,12,30)` |
| `dp1`, … | `string` / `dyn_string` | да | Атрибуты. **`dp` не может быть элементом `dyn`-массива** — каждый указывается отдельно | `"Valve17.opening:_offline.._value"` |
| `var1`, … | тип по атрибуту, **ref** | да | Куда писать | `float x;` |

**Возврат.** `0` — успех, `-1` — сбой.

**Подстановка по умолчанию:** `_offline.._value`.

**Ключевые ограничения**

* Имеет смысл **только если точка данных архивирована**.
* Если на момент `t` значения нет — вернётся значение элемента, **последнее
  сохранённое перед** `t`.
* Читаются только атрибуты конфигов `_original`, `_online`, `_offline`, `_corr`.

```c
dpGetAsynch(makeTime(1996, 3, 5, 12, 30), "Valve17.opening:_offline.._value", x);
```

**Скрипт не создан — функция вне объёма.**

**Типичные ошибки**

* Точка данных не архивировалась — вернётся мусор или ничего.
* Путаница `dyn`-элемента с `dyn`-массивом в первом аргументе.

## dpGetPeriod()

**Синопсис**

```c
int dpGetPeriod(time t1, time t2, unsigned count, string dp1,
                <dyn_type1> &xa1, dyn_time &ta1
                [, string dp2, <dyn_type2> &xa2, dyn_time &ta2]);
```

**Назначение.** Выбирает из архива все значения атрибута за интервал `[t1, t2]` плюс
`count` значений до `t1` и после `t2`.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `t1` | `time` | да | Начало интервала, **локальное время** | `makeTime(2003,9,8)` |
| `t2` | `time` | да | Конец интервала, **локальное время** | `makeTime(2003,9,9)` |
| `count` | `unsigned` | да | Сколько значений взять до `t1` и после `t2` | `1` |
| `dp1` | `string` | да | Идентификатор атрибута | `"Reservoir_1_level.C1.AVG_WT0:_offline.._value"` |
| `xa1` | `dyn_*`, **ref** | да | Массив значений | `dyn_float val;` |
| `ta1` | `dyn_time`, **ref** | да | Массив времён источника, длины как `xa1` | `dyn_time t;` |

**Возврат.** `0` — ок, `-1` — ошибка.

**Особенности**

* Массивы `xa`/`ta` **переинициализируются при каждом вызове** — их длины всегда
  равны.
* Значения **всегда отсортированы по времени источника**. При одинаковом времени
  (вплоть до миллисекунд) — по порядку поступления.
* `dyn_anytype` использовать **нельзя** — нужен конкретный тип `dyn_*`.
* Читаются только `_original`, `_online`, `_offline`, `_corr`.
* Время — **локальное**, не UTC; конвертация внутри. Но `t1` не может быть раньше
  1.1.1970 0:00 UTC.
* Если точку данных переименовывают **одновременно** с запросом — функция вернёт
  ошибку.
* Ограничение числа значений: `[valarch] queryMaxValues`. При превышении — сообщение
  об ошибке, читать через `getLastError()`.

**Соотношение `_original` / `_online` / `_offline`.** У них одинаковый набор атрибутов.
Различаться могут только `_value` и `_stime`. В особых случаях `_online` подхватывает
скорректированное значение (`_default.._value`); если у скорректированного значения
**тот же** источниковый момент, оно заменяет original/offline, иначе `_offline`
просто повторяет `_online`.

**Записи, созданные самим архивом** (старт архивирования, смена архива), попадают в
результат при `count > 0`; опознаются по биту `TIMEINVALID`. С NGA все значения
архивируются со временем изменения, а не активации, поэтому бит не выставляется, а
`count` учитывает все записи.

**Найти самое раннее значение в базе:**

```c
dpGet("myDp.:_start.._original");
dpGet("myDp.:_start.._online");
dpGet("myDp.:_start.._offline");
```

Это надёжнее, чем угадывать границы интервала для `dpGetPeriod()`.

**Обязательное условие:** у элемента должен быть конфиг `_archive`.

> **Проверить его наличие через `dpGet()` нельзя.** `_archive` — конфиг
> архивного менеджера, а не Event Manager, поэтому `dpGet()` по нему всегда
> возвращает `rc = -1` независимо от того, настроен конфиг или нет. Тот же
> отказ даёт `_address`, и по той же причине.
>
> **Отказ в доступе и отсутствие конфига — разные вещи.** Утверждение
> «`rc = -1` значит, что `_archive` не настроен» ошибочно: отказ говорит
> лишь о том, что этот конфиг Event Manager не обслуживает, и ничего - о настройке.

```c
dyn_float val;
dyn_time t;
int ant = dpGetPeriod(makeTime(2003,9,8), makeTime(2003,9,9), 1,
                      "Reservoir_1_level.C1.AVG_WT0:_offline.._value", val, t);
if (ant == -1 || dynlen(val) == 0) {
  DebugN("dpGetPeriod вернул ошибку или значений нет");
} else {
  for (int i = 1; i <= dynlen(val); i++) DebugN(val[i], t[i]);
}
```

### Что измерено на стенде

Проверено на предустановленной точке `ExampleDP_Arg1` (читывается, ничего в ней
не изменяется):

| Проверка | Результат |
| --- | --- |
| `rc` | `0` |
| `dynlen(xa) == dynlen(ta)` | да, всегда |
| значения внутри окна `[t1, t2]` | есть |
| значения вне окна | есть — это и есть работа `count` |
| порядок по времени источника | соблюдён, нарушений 0 |
| конфиг `_address` | отвергнут, `rc = -1` |
| несуществующая точка | `rc = -1` |

**Про `count`.** Это не потолок на общее число значений, а сколько значений
взять **до `t1` и после `t2`**. Поэтому суммарная длина массива заметно больше
`count`: окно 2 минуты при шаге записи ~2 с даёт около 60 значений, и при
`count = 20` возвращается **100**.

Массивы `xa`/`ta` переинициализируются — их длины всегда равны, но зависят от
окна и `count`, поэтому результат нельзя считать заранее.

**Проверено:** `examples/03-read/03_dpGetPeriod.ctl`, 12/12.

**Скрипт.** `examples/03-read/03_dpGetPeriod.ctl`

## dpGetMaxAge()

**Синопсис**

```c
int dpGetMaxAge(unsigned age, string dp1, <type1> &var1
                [, string dp2, <type2> &var2, ...]);
```

**Назначение.** Если значение элемента старше `age` миллисекунд — **дёргает драйвер**
через singleQuery и возвращает свежее значение.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `age` | `unsigned` | да | Возраст значения в **миллисекундах**. `0` — запрашивать у драйвера всегда | `3600000` (1 час) |
| `dp1` | `string` | да | Элемент точки данных | `"System1:EIPtestCompactArrays.BOOL"` |
| `var1` | тип, **ref** | да | Куда писать. Для списка — только `dyn_anytype` | `dyn_anytype var1;` |

**Возврат.** `0` — успех, `-1` — сбой.

Если **периферийного адреса нет** — функция ведёт себя как `dpGet()` и возвращает
значение немедленно, независимо от возраста.

**Осторожно:**

* Выполнение может быть долгим — драйвер ждёт ответа.
* Если драйвер не ответит — функция не вернётся до истечения
  `[all drivers] IOTransitionTimeout` (**по умолчанию 10 секунд**).

**Поддерживается только драйверами:** OPC UA Client, Modbus/TCP, S7Plus, S7, SNMP,
Ethernet/IP, S-Bus, OPC.

```c
dyn_anytype var1;
unsigned ag1 = 3600000;
string dp1 = "System1:EIPtestCompactArrays.BOOL";
int retV = dpGetMaxAge(ag1, dp1, var1);
DebugN("ret:", retV, "value:", var1);
```

**Скрипт.** `examples/03-read/04_dpGetMaxAge.ctl` ✅ проверено, 14/14

## dpGetStatusBit()

**Синопсис**

```c
int dpGetStatusBit(bit64 aStatus, string aBitAttribute);
```

**Назначение.** Извлекает конкретный бит из 64-битного слова состояния.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `aStatus` | `bit64` | да | Любая битовая переменная (в примере `bit32`) | `bit32 status;` |
| `aBitAttribute` | `string` | да | Имя существующего битового атрибута | `":_original.._userbit6"` |

**Возврат.** `0` или `1` — значение бита, `-1` — ошибка.

```c
bit32 status;
string aBitAttribut = ":_original.._userbit6";
int dp;
dpGet("ExampleDP_Bit32.:_original.._status", status);
DebugN("Original Status : " + status);
dp = dpGetStatusBit(status, aBitAttribut);
DebugN("Return " + dp);
```

**Измерено на стенде.** У `_userbit0` **нет отдельного атрибута**:
`dpGetStatusBit` возвращает для него `-1` с сообщением
`Couldn't convert to DpIdentifier`. Биты `userbit1` … `userbit15` отвечают
нормально. Остальные ошибочные случаи (нет такого бита, нет такого атрибута,
нет такого конфига, имя без ведущего двоеточия) дают `-1`.

Биты пишутся через `dpSetTimedWait(0, dpe + ":_original.._userbitN", TRUE)`
и сразу же читаются через `dpGetStatusBit`.

## dpAttributeType()

**Синопсис**

```c
int dpAttributeType(string dp);
```

Возвращает тип данных **атрибута**. Ошибка — `-1`.

```c
if (dpAttributeType("valve17.opening:_original.._value") == FLOAT_VAR) { ... }
if (dpAttributeType("valve17.opening:_original.._value") == INT_VAR)   { ... }
```

Обратите внимание: здесь используются константы `FLOAT_VAR` / `INT_VAR` — это
**другой** набор констант, чем `DPEL_*` (тип переменной CTRL, а не тип элемента
точки данных). Не путайте с `dpElementType()`.
### Таблица констант, измеренная на стенде

| Константа | Значение | Это `<< 16` |
| --- | --- | --- |
| `FLOAT_VAR` | 458752 | 7 |
| `INT_VAR` | 327680 | 5 |
| `BOOL_VAR` | 262144 | 4 |
| `STRING_VAR` | 524288 | 8 |
| `TIME_VAR` | 196608 | 3 |
| _имени константы нет_ | 589824 | 9 |

Код составной битовый: **(базовый тип << 16) | флаги**. На стенде младшие
16 бит всегда нулевые, поэтому базовый тип читается делением на 65536.

Для атрибута `_status` именованной константы **нет** — значение 589824 приходится
задавать числом.

### Что возвращается на практике

| Атрибут | Тип результата |
| --- | --- |
| `_value` | зависит от типа элемента: float → `FLOAT_VAR`, int → `INT_VAR`, bool → `BOOL_VAR`, string → `STRING_VAR`, time → `TIME_VAR` |
| `_stime` | всегда `TIME_VAR`, независимо от элемента |
| `_bad` | всегда `BOOL_VAR`, независимо от элемента |
| `_status` | всегда 589824, независимо от элемента |

Конфиг на результат **не влияет**: `_original` и `_online` дают одинаковое
значение для всех типов элементов.

### Ошибочные случаи

Все дают `-1`:

* несуществующий элемент, конфиг или атрибут;
* пустая строка;
* имя элемента структуры без завершающей точки (`attrfVal:_online.._value`); корень одиночной точки — наоборот, с точкой (`ExampleDP_Arg1.:_online.._value`);
* **корневой элемент типа `struct`** — значения нет, поэтому нет и типа.

**Проверено:** `examples/03-read/07_dpAttributeType.ctl`, 41/41.

**Скрипт.** `examples/03-read/07_dpAttributeType.ctl` ✅ проверено, 41/41

## dpSubStr()

**Синопсис**

```c
string dpSubStr(string dp, int pattern);
```

**Назначение.** Вырезает часть идентификатора точки данных. Возвращает **нейтральную**
(каноническую) форму конфигов и атрибутов.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dp` | `string` | да | Элемент точки данных | `"Valve17.opening:_default.._type"` |
| `pattern` | `int` | да | Константа `DPSUB_*`, см. ниже | `DPSUB_DP` |

**Возврат.** Нужная часть имени либо **пустая строка** при ошибке. Функция **проверяет
существование** точки данных; для несуществующей вернёт ошибку.

**Константы `DPSUB_*`**

| Константа | Что возвращает |
| --- | --- |
| `DPSUB_ALL` | Всю строку имени |
| `DPSUB_SYS_DP_EL_CONF_DET_ATT` | Полный путь с атрибутом |
| `DPSUB_SYS_DP_EL_CONF_DET` | Путь без атрибута |
| `DPSUB_SYS_DP_EL_CONF` | Путь без атрибута и detail |
| `DPSUB_SYS_DP_EL` | Путь без атрибута и конфига |
| `DPSUB_SYS_DP` | Только система и имя точки данных |
| `DPSUB_SYS` | Только система |
| `DPSUB_DP_EL_CONF_DET_ATT` | Без системы |
| `DPSUB_DP_EL_CONF_DET` | Без системы и атрибута |
| `DPSUB_DP_EL_CONF` | Без системы, атрибута и detail |
| `DPSUB_DP_EL` | Без системы, атрибута, detail и конфига |
| `DPSUB_DP` | Только имя точки данных |
| `DPSUB_CONF_DET_ATT` | Только конфиг, detail и атрибут |
| `DPSUB_CONF_DET` | Только конфиг и detail |
| `DPSUB_CONF` | Только конфиг |

```c
string s = dpSubStr("Valve17.opening:_default.._type", DPSUB_DP);
DebugN(s);   // Valve17
```

**Особенность структур.** Для элементов типа `struct` возвращается **индекс**, а не
имя:

```c
dpSubStr("myDp.intStruct.node2", DPSUB_DP_EL);   // "myDp.intStruct[2]"
```

Это регулярное выражение в строках, которые потом используются для доступа к
элементам, нужно учитывать.

### Фактические значения, измеренные на стенде

На элементе `subDp.fVal` входной строкой `subDp.fVal:_online.._value`:

| Константа | Возвращает |
| --- | --- |
| `DPSUB_ALL` | `System1:subDp.fVal:_online.._value` |
| `DPSUB_SYS_DP_EL_CONF_DET_ATT` | `System1:subDp.fVal:_online.._value` |
| `DPSUB_SYS_DP_EL_CONF_DET` | `System1:subDp.fVal:_online.` — с завершающей точкой |
| `DPSUB_SYS_DP_EL_CONF` | `System1:subDp.fVal:_online` |
| `DPSUB_SYS_DP_EL` | `System1:subDp.fVal` |
| `DPSUB_SYS_DP` | `System1:subDp` |
| `DPSUB_SYS` | `System1:` — с двоеточием |
| `DPSUB_DP_EL_CONF_DET_ATT` | `subDp.fVal:_online.._value` |
| `DPSUB_DP_EL_CONF_DET` | `subDp.fVal:_online.` |
| `DPSUB_DP_EL_CONF` | `subDp.fVal:_online` |
| `DPSUB_DP_EL` | `subDp.fVal` |
| `DPSUB_DP` | `subDp` |
| `DPSUB_CONF_DET_ATT` | `:_online.._value` — **с ведущим двоеточием** |
| `DPSUB_CONF_DET` | `:_online.` |
| `DPSUB_CONF` | `:_online` |

Три вещи, которые стоит запомнить:

* **`DPSUB_CONF` возвращает конфиг с ведущим двоеточием** — `":_online"`, хотя
  во входной строке конфиг отделён двоеточием, а не начинается с него. Сравнивать
  с `"_online"` нельзя.
* **`DPSUB_ALL` возвращает каноническую форму** — с префиксом системы, даже если его
  не было во входе. Проверка `dpSubStr(x, DPSUB_ALL) == x` неверна.
* **Неизвестный код константы возвращает всю строку**, а не пустую, то есть
  неотличим от `DPSUB_ALL`. Опечатку в номере константы это не поймает.

Ошибочные случаи (пустая строка): несуществующая точка данных, пустая строка на входе.
Пустой возврат нельзя отличить от существующей точки с пустым именем.

### Непроверенное: вложенные элементы структуры

Утверждение выше про возврат индекса (`myDp.intStruct[2]`) на этом стенде
**не проверено**: создать точку с вложенной структурой через `dpTypeCreate()` не
удалось — плоский формат запрещает повтор имени промежуточного узла и отвечает
`equal element names`. Проверка требует готовой точки с такой структурой.

**Проверено:** `examples/03-read/08_dpSubStr.ctl`, 17/17.

**Скрипт.** `examples/03-read/08_dpSubStr.ctl` ✅ проверено, 17/17

**Типичные ошибки**

* Ожидание `[2]`, а в `sdp`-именах узлов получите индекс.
* Пустой возврат при несуществующей точке данных легко спутать с пустым `dp`-именем.

## dpGetId() / dpGetName()

```c
bool   dpGetId(string dpName, unsigned &dpId, int &elId);
string dpGetName(uint dpId, int elId [, int sysnum = ownSystem]);
```

**Возврат `dpGetId()`.** `true` — DPE существует, `false` — нет (**тогда `dpId` и
`elId` не определены**).

Требования к `dpName`: без подстановок, разрешается до `":"`, **без имени системы**.

```c
unsigned id1;
int id2;
bool x = dpGetId("ExampleDP_Arg1.", id1, id2);
DebugN(x, id1, id2);   // true, 1, 1421
```

**Обратная функция:**

```c
uint dpID;
int elID;
string dpName;
dpGetId("System1:ExampleDP_Arg1.", dpID, elID);
dpName = dpGetName(dpID, elID);
```

**Измерено на стенде.** `dpId` у элементов одной точки совпадает, `elId`
различается. У корня точки `elId = 1`. Идентификаторы устойчивы между
вызовами. `dpGetName()` возвращает имя с префиксом системы; у корня это
`"System1:имя."` — с точкой. Явный `sysnum = 1` совпадает с умолчанием,
несуществующая система даёт пустую строку.

Тип первого параметра - `unsigned`, а **не** `unsigned int`: последнее
не является типом CTL и роняет компиляцию.

> **Ошибка в документации 3.21.6.** Синопсис `dpGetId()` указан как
> `bool dpGetId(string dpName, unsigned int &elId)` — с двумя параметрами, тогда как
> примеры и `dpGetName()` используют **три**: `dpName`, `&dpId`, `&elId`. Фактическая
> сигнатура — три параметра. Это подтверждено примером из документации.

**Скрипты.** `examples/03-read/14_dpGetId.ctl` ✅ 13/13, `15_dpGetName.ctl` ✅ 15/15
