# От референса пользователя до работающей точки данных

> Проверено на CTL 3.18, проект `<проект>`, драйвер Modbus 2, эмулятор TCP 504.
> Две независимые карты: `smart-temp-press.json` (1 slave, 40 элементов) и
> `map.json` (6 slave, 43 элемента). Обе прошли с первого раза.

## Зачем этот документ

Раньше скрипт точки данных писался под карту руками. На каждой новой карте
повторялись одни и те же ошибки, и все они молчаливые — точка создаётся,
конфиг пишется без ошибок, но данных нет:

| Ошибка | Как выглядела |
| --- | --- |
| `FLOAT` там, где в карте `count = 1` | значение приходит битым мусором, `4.13e-39` |
| не задан `_distrib` | драйвер не считает точку своей, ошибок нет |
| не задан `_poll_group` | адрес молча не опрашивается |
| `wordOrder: "ABCD"` вместо `CDAB` | все float-значения перевёрнуты |
| `_drv_ident` числом, а не строкой `"MODBUS"` | адрес не опрашивается |

Ни одну из них нельзя поймать без сверки. Поэтому ручной перенос убран, а
остался один механический шаг: **карта → CTL**.

## Схема

```
референс пользователя          ← приходит текстом, XML, таблицей
        │
        │  разбирает модель, единственное место где нужна голова
        ▼
  map.json                      ← схема из validate-map.js
        │
        ├── validate-map.js      ← механика: разрывы, дубли, count, signed, gen
        │
        ├── gen-modbus-dp.js     ← механика: _datatype, _direction, адреса
        │        │
        │        └── regtype.js  ← общее правило трактовки регистра
        │                 ↑
        │                 └── server.js использует то же правило
        ▼
   *.ctl                        ← готовый скрипт точки, запускается как есть
```

Ключевое: `regtype.js` — **одно** место, решающее, что означает запись карты.
Сервер кодирует им значения, генератор по нему же ставит `_datatype`. Когда
эти два места решали по-разному, `Total_Operating_Hours` приходил как
`bad = 1` с заглушкой `2147483647`: сервер отдал float32, точка читала uint32.

## Правило трактовки регистра

`tools/modbus-sim/regtype.js`, функция `classify(reg, space)`.

| Пространство | `_datatype` | Тип элемента | Направление |
| --- | --- | --- | --- |
| `coils` | 567 `BIT` | `DPEL_BOOL` | 7 — вход/выход |
| `input` | 567 `BIT` | `DPEL_BOOL` | 4 — опрос |
| регистр, `count 1`, `signed` | 561 `INT16` | `DPEL_INT` | 4 |
| регистр, `count 1`, `signed: false` | 563 `UINT16` | `DPEL_INT` | 4 |
| регистр, `count 2`, генератор даёт дробь | 566 `FLOAT` | `DPEL_FLOAT` | 4 |
| регистр, `count 2`, генератор целый, `signed` | 562 `INT32` | `DPEL_INT` | 4 |
| регистр, `count 2`, генератор целый, без знака | 564 `UINT32` | `DPEL_INT` | 4 |

Двухрегистровая запись неоднозначна сама по себе: и `float32`, и `uint32`
имеют `count = 2` и `signed = false`. Намерение снимает генератор:

| Генератор | Трактовка |
| --- | --- |
| `sine` | всегда `float32` |
| `const` с дробным `value` | `float32` |
| `ramp`, `sineInt` | целое |
| `const` с целым `value` | целое |

## Порядок слов

Задаётся в карте, а не в точке OA: скрипт про порядок слов не знает ничего,
это преобразование драйвера.

Стенд WinCC OA 3.18 на `<проект>` и `<проект>` читает **`CDAB`**.
С `ABCD` все float-значения приходят перевёрнутыми:

| Канал | `ABCD` | `CDAB` |
| --- | --- | --- |
| `Firmware_Version` | −4.95e+32 | **3.14** |
| `Energy_Consumption` | −2.36e−20 | **141.83** |
| `Total_Operating_Hours` | `bad = 1`, q = 86 | **40620** |
| `Serial_Number` | 2040745579 | **987654321** |

Это самая дорогая находка при настройке: ошибка не сообщается, а выглядит как
«устройство отдаёт ерунду».

## Порядок работы

### 1. Проверить карту

```powershell
node tools\modbus-sim\validate-map.js tools\modbus-sim\devices\smart-temp-press.json
```

Код возврата: `0` — можно запускать, `1` — ошибки, `2` — файл не прочитан.
Проверяются: непрерывность адресов, дубли, `count`, `signed`, обязательные
параметры генератора, занятость порта.

Предупреждение «все значения константы» означает, что доказать работу
невозможно: значения формально приходят, но не меняются, а это неотличимо от
неверного адреса. Хотя бы часть сигналов должна быть динамической.

### 2. Запустить эмулятор

```powershell
$env:MODBUS_MAP = '...\smart-temp-press.json'
$env:VERBOSE   = '1'
node tools\modbus-sim\server.js
```

Карта перечитывается на лету, перезапуск не нужен.

### 3. Проверить соединения с устройствами

Драйвер опрашивает только те узлы, у которых заполнен **номер драйвера**.
Это самая частая причина «эмулятор работает, а данных нет»:

```ctl
_Mod_Plc_2: DrvNumber=0  ← молчит
_Mod_Plc_1: DrvNumber=2  ← работает
```

`DrvNumber` пишется из CTL, в отличие от большинства конфигов:

```ctl
dpSetTimedWait(0, "_Mod_Plc_2.DrvNumber",     2);
dpSetTimedWait(0, "_Mod_Plc_2.UnitAddress",   2);
dpSetTimedWait(0, "_Mod_Plc_2.HostsAndPorts", "<IP-сервера>:504");
dpSetTimedWait(0, "_Mod_Plc_2.Active",        TRUE);
```

В `HostsAndPorts` подставь адрес своего сервера — в примере он
стоит плейсхолдером. Порт `504` выбран для стенда намеренно:
стандартный Modbus TCP — это `502`, но он привилегированный и на
машине часто занят настоящим шлюзом. На боевом объекте ставь порт
своего шлюза; эмулятор умеет работать на любом, задаётся полем `port`
в `map.json` или ключом `-Port`.

`dpGetAllAttributes` на узле `_Mod_Plc_N` возвращает пусто — узел не является
обычной точкой данных, перечислять атрибуты нечем. Список полей известен:
`DrvNumber`, `PlcNumber`, `UnitAddress`, `Active`, `HostsAndPorts`,
`ConnState`, `Error`, `SentFrames`, `RcvFrames`, `RejFrames`.

### 4. Сгенерировать CTL

```powershell
node tools\gen-modbus-dp.js tools\modbus-sim\devices\smart-temp-press.json `
     --out examples\11-address\20_address_modbus_from_map.ctl `
     --dp STP --dpt stpt_ --drv 2
```

| Ключ | Смысл |
| --- | --- |
| `--out <file>` | куда писать CTL, обязателен |
| `--dp <префикс>` | имя точки; иначе из имени устройства |
| `--dpt <префикс>` | имя типа; иначе `<dp>_t` |
| `--drv <N>` | номер драйвера, по умолчанию 2 |
| `--keep` | не удалять существующую точку перед созданием |
| `--no-verify` | не добавлять блок проверки данных |

Скрипт сам находит группу опроса в проекте по первой точке типа
`_PollGroup` и ничего не спрашивает. Имена элементов приводятся к допустимым
и приводятся в единственное число коллизий переименованием с суффиксом.

### 5. Запустить скрипт

```powershell
.\examples\run-ctl.ps1 -Script examples\11-address\20_address_modbus_from_map.ctl
```

Проект и номера драйверов определяются автоматически из запущенных процессов.
Скрипт сам создаёт точку, привязывает адреса, ждёт данные и проверяет:
у всех элементов `quality_code = 128`, данные пришли, часть значений меняется.

## Результаты прогонов

### `smart-temp-press.json` — 1 slave, 40 элементов

```
элементов всего  : 40
quality = 128    : 40
данные пришли    : 40
значения меняются: 23
PASS=45  FAIL=0
```

| Канал | Значение | Ожидалось |
| --- | --- | --- |
| `Current_Temperature` | 309 | 180..320 |
| `Energy_Consumption` | 141.83 | float 120..480 |
| `Firmware_Version` | 3.14 | float, константа |
| `Total_Operating_Hours` | 40620 | uint32 40000..41000 |
| `Serial_Number` | 987654321 | uint32, константа, стабилен |

Драйвер опрашивает все четыре пространства точно по карте:
`FC1 coils 0..5`, `FC2 input 0..7`, `FC3 holding 0..19`, `FC4 ireg 0..9`.

### `map.json` — 6 slave, 43 элемента

```
элементов всего  : 43
quality = 128    : 43
данные пришли    : 43
значения меняются: 20
PASS=58  FAIL=0
```

Независимая сверка: `Temperature_Int = Temperature`×10, `Pressure_Int` =
`Pressure`×100, `Level_Int` = `Level`×10, `Flow_Int` = `Flow_Instant`×10 —
все сошлись. Совпадение этих четырёх пар возможно только при верной адресации
и верном `_datatype` всех элементов.

## Что делать с новой картой пользователя

1. Разобрать референс в схему `map.json`. Единственное место, где нужна
   модель вместо механики. Сомнения по `wordOrder` и по `count` у 32-битных
   записей — спросить пользователя сразу, а не угадывать.
2. `validate-map.js` — отказ по адресам, дублям, `count`, `signed`.
3. `gen-modbus-dp.js` — скрипт точки.
4. `run-ctl.ps1` — проверка на живых данных.
5. Показать пользователю таблицу соответствия «сигнал → адрес → тип» до
   запуска, чтобы он сверился с референсом.
6. Спросить, оставлять ли созданные точки.

Пункты 2–4 не требуют рассуждений и одинаковы для любой карты.

## Границы применимости

- Генератор не читает референс. Это принципиально: чтение произвольного
  текста без участия модели даёт больше ошибок, чем экономит.
- `count = 4` трактуется как `UINT32` в четырёх словах; на стенде не проверено.
- Порядок байт **внутри** слова на стенде не различался: карты пользуются
  `ABCD` и `CDAB`, то есть различается порядок слов. Если попадётся
  `BADC`, правила надо будет расширять.
- Диагностический вывод `lastAddr` показывает `0..-1` для пространств,
  которых нет в карте. Косметика, на работу не влияет.
