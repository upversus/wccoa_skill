# WinCC OA 3.18 — работа с точками данных из CTL

Справочник проверенных функций, примеры и инструменты. Каждое утверждение
здесь проверено запуском на живом проекте, а не взято из документации.

## Три правила, нарушение которых дороже всего стоит

### 1. Не выдумывать имена функций

`Function not defined` не означает, что функции нет. Значит, что искать надо
не там или не так.

Порядок поиска, обязательный:

1. `docs/99-reference.md` — сводная таблица, там всё, что уже проверено.
2. `docs/<этап>.md` по названию операции.
3. `C:\Sybcom\Kaskad\3.18\scripts\libs\` — исходники библиотек.
4. `C:\Sybcom\Kaskad\3.18\scripts\gedi\` — если функция из GEDI.

Существуют `dpGetAllAttributes`, `dpGetAllDetails`, `dpGetAllConfigs`,
`dpGetElementType`, `dpTypeGet`, `dpNames`.

Не существуют: `dpGetAllDPEs`, `dpGetDPEs`, `dpSetAddress`, `dpCreateType`.
Придуманные имена встречались трижды за одну сессию, каждое стоило итерации.

Если функцию найти не удалось, так и скажи пользователю, а не подставь
близкое по смыслу имя.

### 2. Адрес брать из цельного примера, а не собирать по атрибутам

Конфиг периферийного адреса — это блок из семи атрибутов плюс `_distrib`.
Соберёшь его по частям, получишь точку, которая молча не работает: без
ошибок, без запросов, `_bad = 1`.

Рабочий рецепт целиком: `examples/11-address/06_address_modbus.ctl`.
Обязательный набор: `_distrib.._type` + `_distrib.._driver`, затем
`_address.._type`, `.._reference`, `.._active`, `.._drv_ident` (строкой
`"MODBUS"`), `.._datatype`, `.._direction`, `.._poll_group`.

Подробности и таблица кодов: `docs/11-address.md`.

### 3. Данные, которые не меняются, ничего не доказывают

«Значение пришло и равно 3.5» и «адрес не опрашивается» выглядят одинаково.
Признак успеха один — значение **меняется между срезами**, если сигнал по
референсу динамический.

Поэтому перед проверкой спроси пользователя: эти данные должны меняться? Если
да — снимай два среза с интервалом и сравнивай. Если значение константа по
референсу, так и напиши, что проверить изменение нельзя.

Если на стенде нет OPC UA сервера, честно скажи об этом. Не выдавай
непроверенный путь за рабочий.

## С чего начинать любую задачу

1. **Узнай стенд.** Проект и номера драйверов определяются автоматически:

   ```powershell
   .\examples\run-ctl.ps1 -Script .\lib\probe.ctl
   ```

   В выводе будет строка `Проект определён автоматически: <имя>  драйверы:
   Modbus=N, OPCUA=M`. Проект берётся из запущенных процессов по ключу
   `-PROJ`, номера драйверов — по `-num`.

2. **Найди эталон.** Прежде чем писать новое, посмотри, не сделано ли уже.
   Почти всё, что нужно, лежит в `examples/`. Это надёжнее документации:
   пример проверен запуском, документация описывает 3.21.6, а стенд 3.18.

3. **Прочитай нужный раздел справочника** в `docs/`. Не весь, а по
   операции. Там есть расхождения документации с поведением, помеченные
   явно.

## Инструменты

Всё лежит рядом, пути внутри относительные, переносить можно целиком.

| Инструмент | Что делает | Проверен |
| --- | --- | --- |
| `examples/run-ctl.ps1` | запускает один CTL-скрипт, печатает `DebugN` и сообщения журнала OA, определяет проект и драйверы | да |
| `examples/verify.ps1` | прогоняет весь набор примеров как гейт | да |
| `tools/gen-modbus-dp.js` | генерирует готовый CTL точки данных из карты | да, две разные карты |
| `tools/modbus-sim/validate-map.js` | проверяет карту до запуска эмулятора | да |
| `tools/modbus-sim/regtype.js` | единственное правило трактовки регистра: float или целое | да |
| `tools/modbus-sim/server.js` | эмулятор Modbus TCP без зависимостей | да |
| `tools/gen-opcua-dp.js` | генерирует CTL из CSV-карты, типы берёт с сервера | да, 22/22 |
| `tools/opcuactl/opcuactl.exe` | обход и чтение сервера OPC UA, сторонний, MIT | да, Kepware KEPServerEX |

### Запуск CTL

Скрипты лежат **вне** каталога проекта и запускаются абсолютным путём — это
требование `WCCOActrl.exe`.

```powershell
.\examples\run-ctl.ps1 -Script .\examples\11-address\06_address_modbus.ctl
```

Путь к интерпретатору берётся из `WCCOA_CTR_EXE`, иначе используется
`C:\Sybcom\Kaskad\3.18\bin\WCCOActrl.exe`. Если установка в другом месте:

```powershell
$env:WCCOA_CTRL_EXE = 'D:\WinCCOA\3.18\bin\WCCOActrl.exe'
```

## Карта устройств на Modbus

Референс пользователя приходит текстом. Дальше всё механика, кроме первого
шага.

```
референс  →  map.json  →  validate-map.js  →  gen-modbus-dp.js  →  *.ctl  →  run-ctl.ps1
             разбирает модель                    механика           механика      проверка
```

Полное описание: `docs/12-map-to-ctl.md`.

Ручной перенос карты в скрипт запрещён: он даёт четыре молчаливые ошибки,
и все четыре уже встречались. Скрипт точки не пишут руками.

## Известные границы и дыры

Честный список того, чего в скилле нет или что не проверено.

### Границы проверенного

- **Запись в OPC UA не проверена.** Чтение доказано, запись нет. Узлы
  Kepware имели `AccessLevel = 3`, то есть сервер запись разрешает.
- **Эмулятора OPC UA нет.** Рабочий стенд возможен только с реальным
  сервером. Для Modbus эмулятор есть, для OPC UA нет.
- **Переменные на 64 бита не проверены.** `LLong` и `QWord` Kepware по
  OPC UA не отдаёт, поэтому `Int64` 758 и `UInt64` 759 с элементами
  `DPEL_LONG` и `DPEL_ULONG` на стенде не проверялись.
- **`docs/04-write.md`, `05-subscribe.md`, `08-alerts.md` без примеров
  скриптов.** Текст есть, проверенных `.ctl` нет, `examples/04-write/` пуст.
- **Порядок байт внутри слова не различался.** Карты используют `ABCD` и
  `CDAB`, то есть различается порядок слов. Что будет с `BADC`, неизвестно.
- **`count = 4` для Modbus не проверен.** Трактуется как `UINT32` в четырёх
  словах.
- **Один стенд.** CTL 3.18, драйверы Modbus и OPC UA. На другой версии
  расхождения с документацией 3.21.6 могут быть другими.

### Границы, которые не обойти механически

- **Состав подписки OPC UA не перечислить из CTL.** `dpGetAllAttributes` и
  `dpGetAllConfigs` на точках типа `_OPCUAServer` и `_OPCUASubscription`
  возвращают ноль элементов. Наличие узла проверяется только чтением.
- **Сервер может не отдавать типы, которые есть в карте.** На карте
  `tools/opcua/Functions.csv` шесть тегов `LLong` и `QWord` сервер не
  публикует. Без сверки с сервером они создались бы молча.
- **Таблицу типов бери из установки, а не из примеров.** Полный список
  из 19 кодов: `scripts/libs/examples/opcuaImportExample.ctl`, enum
  `OPCUATransformation`, от `DEFAULT = 750` до `LOCALIZEDTEXT = 768`.
  В примерах проекта таблица урезана до шести, и на ней путаешь `UInt16`
  с `Int16`.
- **Тип элемента обязан совпадать со знаковостью.** `UInt16` в `DPEL_INT`
  станет отрицательным после 32767. Беззнаковым нужен `DPEL_UINT`,
  64-битным беззнаковым `DPEL_ULONG`.

## Уборка

Созданные точки удаляются по договорённости с пользователем, а не молча.
Группы удаляются через `groupDelete` из `dpGroups.ctl`, обычный `dpDelete`
их не берёт.
