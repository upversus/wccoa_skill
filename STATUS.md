Отметка фиксирует состояние проекта на момент, когда стенд приведён в порядок:
объекты, созданные для проверки, удалены, эмулятор остановлен, документация

## Проверено на стенде

| Область | Результат | Пример |
| --- | --- | --- |
| OPC UA, чтение | **41/41** по карте регистров | `11-address/07_address_map.ctl` |
| OPC UA, типы bool / float / int | **6/6** | `11-address/08`, `09` |
| OPC UA, разбор полей адреса | Variant 1 работает, Variant 2 — нет | `11-address/11`, `12`, `13` |
| Modbus, чтение, 6 устройств | **41/41**, пары «вещественное + целое» сходятся | `11-address/07_address_map.ctl` |
| Modbus, запись | **5/5** с обеих сторон, драйвер шлёт FC15 и FC16 | `11-address/10_address_modbus_write.ctl` |
| Алиас, единица, формат, описание | **23/23**, восемь функций | `02-config/01_metadata_functions.ctl` |

Независимая проверка адресации Modbus: `Temperature_Int` = `Temperature`×10,
`Pressure_Int` = `Pressure`×100, `Level_Int` = `Level`×10,
`Flow_Int` = `Flow_Instant`×10. Все четыре сошлись, значит адреса верны, а не
просто «данные приходят».

## Главное, что выяснено и записано

| Факт | Где |
| --- | --- |
| Конфиги пишутся только через `dpSetTimedWait(0, …)` | `docs/11-address.md` раздел 1 |
| `_address.._poll_group` обязателен **для Modbus**, для OPC UA не нужен | раздел 8.1 |
| Для каждого Slave ID нужна точка `_Mod_Plc`, создаёт пользователь | раздел 5.3 |
| Драйвер группирует записи: шлёт FC15 и FC16, а не FC5 и FC6 | раздел 5.4 |
| Направление 5 (`OUTPUT_SINGLE`) значение на устройство не отправляет | раздел 5.4 |
| `dpExists` для имени типа всегда FALSE, existence проверяется `dpTypeGet` | раздел 8.3 |
| `dpTypeDelete` асинхронен, нужен цикл удаления | раздел 8.3 |
| `dpNames` фильтрует по имени, а не по типу | раздел 8.3 |
| `dpSet*` и `dpGet*` принимают имя элемента **без** завершающей точки | `docs/02-config.md` |
| В CTL есть `substr` и `strpos`, индексы с нуля | раздел 8.3 |
| Схема адреса OPC UA: `Server$Subscription$Kind$Variant$Item` | раздел 5.1.1 |
| Сервер и Подписка берутся из `_OPCUAServer` и `_OPCUASubscription` | раздел 8.2 |

## Инструмент

`tools/modbus-sim` — свой Modbus TCP сервер вместо `mtcpServerEmulator`.
Пять файлов, зависимостей нет. Причина: GUI-эмулятор не перечитывает
конфигурацию без перезапуска, а `node-modbus` и `jsmodbus` с npm годятся
только как клиенты.

```
tools\modbus-sim\modbus-sim.ps1 start | stop | restart | status
```

Карта в `map.json` подхватывается на лету: проверено изменением диапазона,
WinCC OA через три секунды читала новое значение без перезапуска сервера,
драйвера и проекта.
