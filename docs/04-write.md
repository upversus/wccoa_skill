# 04. Запись мимо Event Manager и ожидание значения
> ## ⛔ Раздел вне объёма работ
>
> **Демонстрационные скрипты не создаются (4 штуки):** 01_....ctl,
> 02_....ctl, 03_....ctl, 04_....ctl.
>
> Исключено по решению владельца стенда: функции этого этапа редко используются.
> Дополнительно: `dpDirectRead()` и `dpDirectWrite()` в CTL 3.18 **отсутствуют** -
> это измерено ранее и зафиксировано ниже. Поэтому первые два скрипта из четырёх
> невозможно написать в принципе.
>
> Материал ниже остаётся как справочная заметка.


> ## ⛔ `dpDirectRead()` и `dpDirectWrite()` В CTL 3.18 ОТСУТСТВУЮТ
>
> **✓ Измерено на CTL 3.18:** обе функции **не определены**. Скрипт с ними не
> компилируется:
>
> ```
> CTRL, SEVERE, 176, Uncaught exception in thread started at main:
> CTRL, SEVERE, 72, Function not defined, <файл>  Line: N, dpDirectRead
> ```
>
> В документации 3.21.6 они описаны и отнесены к OPC UA. Значит это функции,
> появившиеся **после 3.18**. На текущем стенде их писать нельзя.
>
> **Что использовать вместо:** обычное чтение через `dpGet()`
> ([03-read.md](03-read.md#dpget)). Для OPC UA связка работает и проверена:
> точка данных с конфигом `_address` получает значение в `_online.._value`
> без всякого прямого доступа — см. [11-address.md](11-address.md).
>
> **Остальной материал этого файла** (`dpCopyOriginal`, `dpWaitForValue`)
> актуален. Разделы про `dpDirectRead`/`dpDirectWrite` оставлены как справка
> для более новых версий.

Прямой доступ к PLC и блокирующее ожидание нужного значения. Здесь же — перенос
original-значений между точками данных.

> **Ограничение драйвера.** `dpDirectRead()` и `dpDirectWrite()` в 3.21.6
> поддерживаются **только драйвером OPC UA**. На остальных драйверах они вернут ошибку.

---

## dpDirectRead()

**Синопсис**

```c
int dpDirectRead(uint timeout, string dp1, <type1> &var1
                 [, string dp2, <type2> &var2, ...]);
```

**Назначение.** Читает значения **напрямую из PLC**, минуя кэш и online-конфиг.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `timeout` | `uint` | нет | Таймаут в **миллисекундах**. По умолчанию — `IOTransitionTimeout` (10 000 мс). `0` → применяется минимум ~1 с | `10000` |
| `dp1`, `dp2`, … | `string` | да | Конфиги (атрибуты), которые читаем | `"dp1.:_original.._value"` |
| `var1`, `var2`, … | тип, **ref** | да | Куда писать | `float v;` |

**Возврат.** `-1` при ошибке. **Успех возвращается только если значение действительно
прочитано из оборудования.**

> Это ключевое отличие от всех прочих `dp*()`: те возвращают `0`, когда запрос
> **успешно отправлен** в Event Manager, а ошибки, возникшие позже, видны только
> через `getLastError()`. Здесь `0` означает фактическое чтение.

**Таймауты**

* У OPC UA есть отдельный `uaCallTimeout` (по умолчанию 10 000 мс). Если таймаут
  функции больше — приоритет у таймаута сервис-вызова OPC UA, запрос истекает на
  уровне протокола.
* Истечение таймаута (например, PLC не ответил) → ошибка.
* На длительность ожидания влияют и другие параметры драйвера.

**Какие конфиги читаются.** Только `_original.._value` и
`_original.._userBits/status64`. Попытка прочитать другой конфиг вернёт ошибку.

**Побочные эффекты.** Успешный вызов **обновляет значения элементов** (как при single
query); обновлённые значения имеют установленный бит состояния `_from_SI`.

**Ошибки.** Через `getLastError()` — в том числе от Event Manager. Каталог сообщений —
`directRead.cat`. Подробности извлекаются из `dyn_errClass`:

| Функция | Что даёт |
| --- | --- |
| `getErrorCode()` | Код ошибки, интерпретируется по `directRead.cat` |
| `getErrorDpName()` | Какой DPE вызвал ошибку |
| `getErrorManId()` | Какой менеджер установил ошибку (`DRV`, `EVENT`, …) |
| `getErrorText()` | Текст ошибки с дополнительной информацией |
| `getErrorUserData()` | **Протокольный** код ошибки, если он есть |

**Протокольные коды — не парсить текст.** Пример из документации: `getErrorCode()`
возвращает `0004` («Direct write to $DP failed: … 12345»), а точный протокольный код
`12345` лежит в `getErrorUserData()`. Текст парсить не нужно.

**Скрипт не создан — раздел вне объёма.**

**Типичные ошибки**

* Вызов на драйвере кроме OPC UA.
* Чтение не `_original` конфигов.
* Путаница смысла `0` с остальными `dp*()` — здесь `0` сильнее обещания.

## dpDirectWrite()

**Синопсис**

```c
int dpDirectWrite(uint timeout, string dp1, <type1> var1
                  [, string dp2, <type2> var2, ...]);
int dpDirectWrite(dyn_string dpnames, dyn_anytype values);
```

**Назначение.** Пишет значения **напрямую в PLC**.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `timeout` | `uint` | нет | Миллисекунды, по умолчанию 10 000. `0` → минимум ~1 с | `10000` |
| `dp1` / `dpnames` | `string` / `dyn_string` | да | Записываемые точки данных | `"dp1.:_original.._value"` |
| `var1` / `values` | любой | да | Значения. Для массивов длины должны совпадать | `1` |

**Возврат.** `-1` при ошибке; успех — только при фактической записи **и получении
подтверждения** от оборудования.

**Ошибки.** Каталог `directWrite.cat`, детали — те же
`getErrorCode()` / `getErrorDpName()` / `getErrorManId()` / `getErrorText()` /
`getErrorUserData()`.

**Какие конфиги пишутся.** Только `_original.._value` и
`_original.._userBits/status64`. Остальные — ошибка.

**Ограничение на subindex.** Не поддерживаются элементы, представляющие **часть**
набора данных в PLC — например, индекс внутри массива или бит внутри `INT`.
Адреса с subindex вернут ошибку.

**Побочные эффекты.** Результат запроса можно отслеживать через биты состояния в
`_corr_value` — они показывают, был ли прямой запрос записи успешным.

**Скрипт не создан — раздел вне объёма.**

**Типичные ошибки**

* Адрес с subindex → ошибка, писать нельзя.
* Успех `0` означает подтверждение от PLC, а не «сообщение отправлено».

## dpCopyOriginal()

**Синопсис**

```c
void dpCopyOriginal(string dpSource, string dpDestination, int &error);
```

**Назначение.** Копирует original-значение исходной точки данных в целевую,
вместе со значениями всех её элементов.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpSource` | `string` | да | Исходная точка данных | `"ExampleDP_Arg1"` |
| `dpDestination` | `string` | да | Целевая точка данных. **Должна существовать — функция её НЕ создаёт** | `"ExampleDP_Arg2"` |
| `error` | `int` | да, **ref** | Код ошибки | `0` |

**Возврат.** `void`; ошибка — в `error`.

**Коды ошибок `dpCopyOriginal()`**

| Код | Значение |
| --- | --- |
| `0` | Успех |
| `-1` | Исходная точка данных не существует |
| `-2` | Целевая точка данных пуста |
| `-3` | Квитирование невозможно |
| `-4` | Деактивация тревоги невозможна |
| `-5` | Ошибка при установке конфигов |
| `-6` | Ошибка при запросе конфигов |
| `-7` | Ошибка при запросе содержимого конфигов |
| `-10` | Целевая точка данных не существует |
| `-11` | Несовпадение типов точек данных |
| `-12` | Исходная и целевая точки данных совпадают |

**Правила**

* Типы исходной и целевой точек данных должны **совпадать**.
* Значения элементов копируются автоматически, перечислять их не нужно.
* Копирование **между разными системами** разрешено (например, System1 → System2).

```c
int error;
dpCopyOriginal("ExampleDP_Arg1", "ExampleDP_Arg2", error);
DebugN(error);
```

**Скрипт не создан — раздел вне объёма.**

**Типичные ошибки**

* Передать несуществующую целевую точку данных и удивляться коду `-10`.
* Ожидать, что функция создаст целевую точку данных — не создаст.

## dpWaitForValue()

**Синопсис**

```c
int dpWaitForValue(dyn_string dpNamesWait, dyn_anytype conditions,
                   dyn_string dpNamesReturn, dyn_anytype &returnValues,
                   time timeout [, bool &timerExpired]);
```

**Назначение.** Блокируется до тех пор, пока значения указанных точек данных **не
изменятся** так, чтобы удовлетворять условиям. Это «одноразовый `dpConnect()`»:
подписаться сразу на несколько точек и получить значения, когда условие выполнится.

**Параметры**

| Имя | Тип CTRL | Обяз. | Описание | Значение для примера |
| --- | --- | --- | --- | --- |
| `dpNamesWait` | `dyn_string` | да | Точки, значения которых сравниваются с условиями | `makeDynString("_PanelOff.PanelName:_original.._value")` |
| `conditions` | `dyn_anytype` | да | Желаемые значения. Типы должны совпадать с типами `dpNamesWait` | `conditions[1] = "child.pnl";` |
| `dpNamesReturn` | `dyn_string` | да | Точки, значения которых вернуть. Может совпадать с `dpNamesWait` | то же |
| `returnValues` | `dyn_anytype` | да, **ref** | Возвращённые значения | `returnValues` |
| `timeout` | `time` | да | Сколько ждать. **`0` = ждать бесконечно** | `t = 5;` |
| `timerExpired` | `bool` | нет, **ref** | `TRUE`, если сработал таймаут | `expired` |

**Возврат.** `0` — условие выполнено, `-1` — ошибка.

**Поведение**

* При истечении таймаута `returnValues` **не изменяются**.
* Если условие уже выполнено на момент вызова **и** ни в одной из точек значения не
  меняются — функция всё равно будет ждать изменения. Функция ждёт именно
  **изменения значения**.

```c
time t;
dyn_string dpNamesWait, dpNamesReturn;
dyn_anytype conditions, returnValues;
int status;

dpNamesWait   = makeDynString("_PanelOff.PanelName:_original.._value");
conditions[1] = "child.pnl";
dpNamesReturn = makeDynString("_PanelOff.PanelName:_original.._value");
t = 5;

ChildPanelOn("child.pnl", "child", "", 0, 0);
status = dpWaitForValue(dpNamesWait, conditions, dpNamesReturn, returnValues, t);
```

**Ожидание.** **Blocking** (Waiting Control function).

**Скрипт не создан — раздел вне объёма.**

**Типичные ошибки**

* `timeout = 0` — вечное ожидание, скрипт не завершится никогда.
* Условие уже выполнено, но значений никто не меняет → вечное ожидание.
* Не забыть `dpSet()` на очистку значения после срабатывания условия.

## Связи

```
dpSet() ──▶ значение ──▶ драйвер ──▶ PLC
dpDirectWrite() ──▶ напрямую в PLC (только OPC UA, только _original.._value)

dpGet()        ──▶ значение из OA
dpDirectRead()  ──▶ значение напрямую из PLC (только OPC UA)

dpCopyOriginal() ──▶ перенос original между точками (в т.ч. между системами)
dpWaitForValue() ──▶ блокирующее ожидание условия
```

Реакция на изменения в фоне — [05-subscribe.md](05-subscribe.md).
