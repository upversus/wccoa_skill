# Раздел 05-subscribe: реализация

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Вернуть раздел 05 в объём: два проверенных примера на `dpConnect` и `dpConnectUserData`, обновлённая документация и счётчики.

**Architecture:** Подписчик живёт после `main()` и печатает каждый вызов колбэка; отдельный служебный скрипт ставит значения через `dpSet` из другого процесса. Проверка — по сводке `--- PASS= N  FAIL= 0 ---` в stdout подписчика.

**Tech Stack:** WinCC OA CTL 3.18 (`WCCOActrl.exe`), PowerShell-обёртки `run-ctl.ps1` и `verify.ps1`.

**Spec:** `docs/superpowers/specs/2026-11-03-05-subscribe-design.md`

## Global Constraints

- `.ctl` пишутся **без BOM** (первые байты не `EF BB BF`).
- Комментарии в скриптах — по-русски, как во всех существующих примерах.
- Имена заглушек в колбэках — с префиксом `val_`.
- Свои объекты: тип `sub_t`, точка `dpdemo_sub`, элемент `value` типа `DPEL_FLOAT`.
- Подписка — на `dpdemo_sub.value:_online.._value`, `answer=TRUE` явно.
- `dpDisconnect*` в скриптах **не используются** (на этом этапе не реализуются).
- UI-функции (`setValue` и подобные) не вызываются — только в комментарии.
- Новые `.ps1` не создаются; правки только в существующие, с сохранением их кодировки.

## Review Focus

- **Колбэк не приходит в отдельный процесс.** Ожидание: `dpSet` из триггера
  вызывает колбэк подписчика. Проверка — Task 1, проба до написания примеров.
- **`answer=TRUE` не даёт вызова при регистрации.** Ожидание: до первой записи
  есть один вызов с начальным значением `0.0`. Проверка — Task 2, отдельная
  проверка `initialSeen`.
- **Сравнение float по равенству.** Ожидание: `22.3`, записанное в FLOAT,
  читается как `22.299999...`. Проверка — Task 2, сравнение с допуском `0.001`.
- **Путь к stdout не виден при `-LongRunning`.** Ожидание: после трёх команд
  оператор знает, какой файл читать. Проверка — Task 1, шаг 5.
- **Счётчики в документации расходятся с файлами.** Ожидание: число примеров
  равно фактическому пересчёту. Проверка — Task 5, шаг 1.

- [ ] **Step 1: Написать `01_dpConnect.ctl`**

Шапка: назначение, ссылка `docs/05-subscribe.md`, порядок проверки из трёх
команд (как в спеке), предупреждение «скрипт не завершается сам — это норма».

Константы и поведение:

```c
string DPT = "sub_t";
string DP  = "dpdemo_sub";
float val_fNewValue;        // заглушка: сюда попадает значение из колбэка
int   nChanges = 0;
bool  initialSeen = FALSE;
dyn_float EXPECTED = makeDynFloat(22.3, 47.5, -5.25, 100.0);   // индексы с 1
```

Сравнение float — только с допуском, своей функцией (в репозитории нет ни
одного `fabs`, полагаться на него нельзя):

```c
bool closeEnough(float a, float b)
{
  float d = a - b;
  if (d < 0) { d = -d; }
  return d < 0.001;
}
```

`main()`: создать тип и точку идемпотентно (`dpTypeGet` / `dpExists`), поставить
начальное `0.0`, затем `dpConnect("onValue", TRUE, DP + ".value:_online.._value")`,
напечатать `rc` и `getLastError()`.

Колбэк:

```c
void onValue(string dp, float fNewValue)
{
  if (!initialSeen && nChanges == 0 && closeEnough(fNewValue, 0.0))
  { initialSeen = TRUE; dpdCheck("answer=TRUE: вызов при регистрации", TRUE); return; }

  dpdCheck("имя DPE содержит точку подписки", strpos(dp, DP + ".value") >= 0);
  if (nChanges < 4)
    dpdCheck("значение " + (nChanges + 1) + " совпало",
             closeEnough(fNewValue, EXPECTED[nChanges + 1]));

  nChanges++;
  val_fNewValue = fNewValue;
  if (nChanges >= 4) dpdSummary();
}
```

`dpdCheck`, `dpdSummary`, счётчики `dpdPass`/`dpdFail` — самодостаточный блок,
идентичный `examples/_lib.ctl` (как в остальных примерах).
