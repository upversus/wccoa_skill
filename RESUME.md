## Найдено при написании `01_dpGet.ctl`

Признак существования конфига через `_type` **не универсален**:

* `_address` — тип материализован, `_type` честно даёт `16`, признак работает;
* `_online` — `_type` равен `0` **даже при настроенном конфиге**, который
  отдаёт `_value` и `_stime`. Признак не работает;
* `_type` rc различает не «настроен/нет», а «известно ли системе имя»:
  `_alert_class` → `rc=0`, выдуманное `_nonsense_cfg` → `rc=-1`;
* надёжный общий признак — читать атрибут данных конфига (`_stime`,
  `_value`) и смотреть `rc`: `0` — настроен, `-1` — нет.

Дополнительно: путь к конфигу **корневого** элемента требует точки —
`dp.:_online.._type`; без точки `DP does not exist`. У корня типа `struct`
конфига `_online` нет вовсе: корень не несёт значения.

Исправлено в `docs/03-read.md` и `docs/11-address.md`. Пробник сохранён:
`examples/03-read/exp/probe_type.ctl`.

Ещё в CTL: `dyn_dyn_dpid` не существует, `dpNameSearch` так не вызывается.

## Семантика, влияющая на реализацию

Прочитано в `docs/03-read.md`, учтено:

* `dpGetAsynch()` читает из архива на момент времени источника. **Работает
  только для архивированных точек.** Если на момент `t` значения нет —
  вернётся последнее сохранённое перед `t`. Читаются только конфиги
  `_original`, `_online`, `_offline`, `_corr`. Время не раньше
  1.1.1970 0:00 UTC.
* `dpGetPeriod()` требует конфиг `_archive` у элемента. Массивы `xa`/`ta`
  переинициализируются при каждом вызове. `dyn_anytype` использовать
  **нельзя** — нужен конкретный `dyn_*`. Время локальное. Ограничение числа
  значений: `[valarch] queryMaxValues`.
* Надёжный способ найти самое раннее значение в базе:
  `dpGet("myDp.:_start.._original")`, а не угадывать границы интервала.

## Грабли, на которые уже наступали

| Грабли | Следствие |
| --- | --- |
| `dpNames()` возвращает имена **с префиксом системы** | склеивать `dp + "." + имя` нельзя, будет `DP does not exist`. `dpGet` принимает такое имя и так |
| `dpExists()` для имени типа всегда `FALSE` | существование типа проверяется только `dpTypeGet` |
| `dpTypeDelete()` асинхронен | удалять в цикле, пока `dpTypeGet` не перестанет видеть |
| `dpDelete()` асинхронен | ждать исчезновения перед удалением типа |
| `.ps1` без BOM не запускается | PowerShell 5.1 читает как ANSI, кириллица ломает разбор |
| `Start-Process -NoNewWindow` с перенаправлением | процесс удерживает трубу, вызов не возвращает управление |
| `-num >= 255` | интерпретатор завершается с кодом 1, молча печатая nothing |
| Неизвестное имя функции в CTL | `SEVERE, 72, Function not defined` на этапе компиляции |
| Перегрузка функций в CTL | не поддерживается, нужны разные имена |
| `dpSet*` / `dpGet*` | имя элемента **без** завершающей точки; с точкой `rc=-1` |

## Протокол проверки

Пример обязан быть самодостаточным и повторяемым:

1) создаём нужный тип точки данных;
2) создаём точку данных этого типа; если проверяем конфигурацию адреса —
   навешиваем `_address`, прописывая адрес Modbus или OPC UA по тесту;
3) удаляем и точку данных, и тип.

Зависимость от заранее существующих чужих объектов — нарушение протокола.
На этом споткнулся `11-address/04_address_recreate.ctl`: он требовал тип
`for_test_OPCUA` и точку `f1`, удалял `f1` и не восстанавливал, из-за чего
второй прогон давал 2/19. Переписан по протоколу, проверен дважды подряд.

## Как запускать проверки

Разовый запуск с полным выводом:

```
examples\run-ctl.ps1 -Script <путь> -Num 245 -WaitSeconds 280
```

Прогон с разбором сводок и кодом возврата:

```
examples\verify.ps1 -Script .\03-read\01_dpGet.ctl
examples\verify.ps1 -Section 03-read
examples\verify.ps1 -All
```

`verify.ps1` разбирает четыре формата сводки (`PASS=/FAIL=`,
`успешно/неудачно`, `успешно N из K`, отсутствие сводки), печатает таблицу и
возвращает 1 при сбоях или примерах без сводки. Перед прогоном Modbus
предупреждает, если порт 504 молчит.

Путь к скрипту обязан быть абсолютным, `-Num` меньше 255. Эмулятор Modbus
остановлен, порт 504 свободен — перед проверками Modbus поднять
`tools\modbus-sim\modbus-sim.ps1 start`.
