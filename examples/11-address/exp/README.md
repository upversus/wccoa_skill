# Исследования: `examples/11-address/exp/`

Здесь лежат разовые проверки, которые выясняли конкретный факт. Они не часть
рабочего набора — рабочие примеры в родительской папке, от `01_` до `09_`.

**Зачем их хранить, а не удалить:** часть выводов была ложной, и именно это
ценно — на них уже наступали грабли. Пометка «вывод ложный» означает, что
скрипт нельзя использовать для выводов, но код показывает, как вопрос
ставился.

## Как читать пометки

| Пометка | Значение |
| --- | --- |
| **вывод верен** | факт подтверждён, на него можно опираться |
| **вывод ложный** | вывод неверен, скрипт показывает ошибку в рассуждении |
| **полезен** | метод применим повторно |
| **не отработал** | запускался, но задачу не решил |

## Modbus: ложные выводы

Здесь сосредоточено то, обо что мы споткнулись. **Выводы этих скриптов
неверны**, но причины ошибок важны.

| Файл | Что проверял | Почему вывод ложный |
| --- | --- | --- |
| `exp_modbus_int.ctl` | перебор типов на адресе 0 | адрес не отдавался эмулятором, тип тут ни при чём |
| `exp_modbus_sweep.ctl` | какие адреса отвечают | одновременный опрос 22 адресов, драйвер обслуживал только младшие |
| `exp_modbus_map.ctl` | карта адресов 0…40 | **41 одновременный адрес** — карта целиком артефакт исчерпания очереди |
| `exp_modbus_line.ctl` | граница рабочего пространства | те же две ошибки плюс не тот тип преобразования |
| `exp_modbus_alive.ctl` | жив ли эмулятор | вывод «новые регистры не отдаются» не подтвердился; метод разделения хороший |
| `exp_modbus_width.ctl` | соответствие ширины регистра и типа | не отработал, заменён на `exp_modbus_fc.ctl` |

**Общий урок трёх последних скриптов:** одновременный опрос десятков адресов
на одном драйвере даёт не карту адресов, а карту очереди запросов. Проверять
надо небольшими группами или по одному.

## Методы поиска причины

| Файл | Что делает | Итог |
| --- | --- | --- |
| `exp_modbus_diff.ctl` | снимает все атрибуты `_address` эталона и своего объекта и печатает их рядом | **вывод верен, скрипт ключевой.** Именно сравнение показало `_poll_group`: у эталона `System1:_1s`, у скрипта пусто. Пять таких гипотез до этого проверяли адреса, типы и коды функций |
| `exp_modbus_seq.ctl` | проверяет адреса строго по одному: создал, подождал, прочитал, удалил | **вывод верен** — после появления `Fill01` адрес 0 заработал, что подтвердило диагноз пользователя про разрывы |
| `exp_modbus_wait.ctl` | оставляет одну точку на 30 с и следит за меткой времени | **вывод верен** — дело было не во времени. Полезно, чтобы не искать не там |

## Не воспроизводятся на текущем стенде

`exp_map_probe.ctl`, `exp_modplc4.ctl` и часть `exp_modbus_*` описывают
состояние **стенда с одной конфигурацией эмулятора**. Сейчас эмулятор
настроен на шесть устройств из карты регистров, поэтому эти скрипты
покажут другие числа. Историческая ценность сохранена, практическая — нет.

## Общее

| Метод | Где применён |
| --- | --- |
| Изоляция одного параметра за прогон | `exp_modbus_dir.ctl`, `exp_modbus_fc.ctl` |
| Сравнение всех атрибутов эталона и своего объекта | `exp_modbus_diff.ctl` → нашёл отсутствующий `_poll_group` |
| Один адрес за раз, с ожиданием | `exp_modbus_seq.ctl` |
| Снимок «до» и «после» с записью в лог | `exp_mb_before.ctl`, `exp_mb_fixpoll.ctl` |
